## Objective

In the inspector, clicking a slider's numeric readout (Exposure, Contrast, Highlights, Shadows, Texture, and the rest) turns it into a text field where the user types an exact value. Return commits, Escape cancels. Only values valid for that control are accepted; anything else is rejected with visible feedback and never applied.

## Context

Slider readouts are display-only today (for example `LightInspectorView.readout(for:)`, which formats `+0.00 EV` or `+0`). The sliders are all `NeutralOriginSlider` (`Views/NeutralOriginSlider.swift`, an `NSViewRepresentable` with a `range` and stepping), used in 13 places: Light, Color, Effects, Develop, Look, Crop, Temperature, and Masking. Each already knows its range and step. The typed value must come from that same range, so the validation rule has one source.

Requested by the user: values must be numeric and match the field's requirements (if a field runs 0-100, the typed number must be in 0-100), or it errors.

## Acceptance criteria

- [ ] Clicking a slider's value readout (single click) swaps it for an inline numeric field, pre-filled and fully selected, with the same width and alignment so the row does not shift. Return commits, Escape or clicking away cancels and restores the old readout.
- [ ] Input is parsed as a number in the control's own units (for example EV for Exposure, and degrees for Temperature if that control uses Kelvin). A unit suffix or leading `+` is accepted. Non-numeric text is rejected.
- [ ] A value outside the control's range is rejected, not clamped. The field shows an error state (red outline and a short message such as "Enter -100 to 100"), keeps focus, and nothing is applied until the value is valid.
- [ ] A valid value goes through the same path as a slider drag (same undo step, same persistence and render update) and snaps to the control's step. Typing the same value as the current one creates no undo step.
- [ ] The shared helper that parses and validates (range, step, formatting) is a separate, unit-tested type. Tests cover valid values, out-of-range at both bounds, non-numeric text, empty text, locale decimal separators, and step snapping.
- [ ] Works for all 13 `NeutralOriginSlider` call sites through the shared component, not per-view copies. Masking sliders and Crop sliders are included, or any excluded one is listed in the review comment with a reason.
- [ ] Accessible: the field has the control's accessibility label, the value is announced on commit, and the error is announced.
- [ ] Double-click-to-reset on the slider and existing keyboard behavior are unchanged. `swift build` is warning-free and `scripts/ci-tests.sh fast` exits 0 (serial too if an AppKit test changes).

## Implementation notes

- Prefer one reusable value-entry control used by `NeutralOriginSlider` rather than editing each inspector. Use `FormatStyle`/`NumberFormatter` for locale-correct parsing.
- Reject, do not clamp: the user asked that out-of-range input errors.
- Swift 6 mode clean: no `@unchecked Sendable`, `nonisolated(unsafe)`, `@preconcurrency`, or `#available` branches. No new dependencies.
- Do not run `scripts/run-kromora-capture.sh`. Preserve unrelated working-tree changes.
- Related: KRMA-1010 (Reduce Motion for inspector animation), KRMA-960 (String Catalog, for the error messages).
