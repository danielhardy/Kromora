## Objective

`StoredEditAdoptionTests` must fail at the deadline instead of spinning until the CI job is killed.

## Context

`waitForPreparationToStart` (`Tests/KromoraKitTests/StoredEditAdoptionTests.swift`, around line 89) records `XCTAssertLessThan(Date(), deadline, ...)` and then keeps sleeping. `XCTAssert` does not throw, so a missed deadline never leaves the loop. The 2026-10-14 review also asks that teardown release every gate these tests hold.

KRMA-967 (ready) is the separate cleanup of `while ... Task.yield()` loops in other files. Do not edit those files here. KRMA-927 previously fixed a teardown hang in this class; read it so you do not undo that fix. Parent epic: KRMA-994. Review, verification quality.

## Acceptance criteria

- [ ] When preparation has not started by the deadline, the wait throws (or otherwise returns to XCTest) with the timeout error. It does not call `XCTAssert` and continue.
- [ ] Every gate this class acquires is released in teardown on both success and failure.
- [ ] The existing adoption tests still pass: `swift test --filter StoredEditAdoptionTests`.
- [ ] `scripts/ci-tests.sh fast` exits 0. If a different test fails, do not weaken this wait to hide it.
