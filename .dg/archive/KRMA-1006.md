## Objective

Choosing a library in Settings, and writing the disposable index during shutdown, must not do package filesystem work synchronously on the main actor.

## Context

`ActiveLibraryChooser.choose` (`Sources/KromoraKit/Presentation/ActiveLibraryChooser.swift`, around line 63) calls `selection.choose` on the main actor. `ActiveLibrarySelection` validates the package synchronously (`Sources/KromoraKit/Models/ActiveLibrarySelection.swift`, around line 57). Shutdown can write the whole disposable index synchronously (`PortableLibrarySession.swift`, around line 732). No timings were taken.

KRMA-1011 owns relaunch sequencing in the same chooser. Do not change when the new process starts. KRMA-1005 owns lease renewal for copy and removal. KRMA-996 owns failed rating retries. If the shutdown index write is the culling index, a failed write must still be visible through that ticket's flush result rather than dropped.

Parent epic: KRMA-994. Review finding 10.

## Acceptance criteria

- [ ] Settings validation of the chosen package runs off the main actor. The button's action returns to the UI before a slow volume would finish, and a validation error still appears in `errorMessage`.
- [ ] The shutdown index write runs off the main actor and is awaited before the session reports that shutdown finished. A write error is surfaced, not ignored.
- [ ] Authority is still checked at the write, not only in the UI preflight.
- [ ] Tests use a temp package. Include one validation failure. Do not require a slow external disk; mention in the comment that external-volume timing was not measured.
- [ ] `swift build` is warning-free. `scripts/ci-tests.sh fast` exits 0.
