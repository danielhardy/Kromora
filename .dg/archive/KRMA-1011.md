## Objective

Choosing a library and relaunching must start the new process only after the current library has flushed and released its lease, and a failed launch must not quit the current process.

## Context

`AppKitRelauncher.relaunch` (`Sources/KromoraKit/Presentation/ActiveLibraryChooser.swift`, around line 11) calls `NSWorkspace.shared.openApplication` and ignores the completion error, then calls `NSApp.terminate`. The new instance can start before the old lease is released, including when the user picks the library that is already open. Canceling quit, or a failed launch, has no coherent outcome. This was found by reading the code, not by a runtime race.

KRMA-1006 moves package validation off the main actor in `choose()`. Do not move that validation here. Do not change the rule that the library choice applies on the next launch rather than swapping the open session. Parent epic: KRMA-994. Related done work: KRMA-988 (Choose Library).

## Acceptance criteria

- [ ] Relaunch waits until pending edits and culling state have flushed and the open package lease is released. If flush fails, the user sees the existing save failure choice and the new process does not start.
- [ ] The replacement process is launched only after that release. If `openApplication` fails, the current process stays running and `errorMessage` explains it.
- [ ] Choosing the already-open library does not start a second instance that contends for the lease. Either skip relaunch with a clear status, or relaunch only after release. Tests must show the lease is not held by the old session when the new launch is requested.
- [ ] Use the existing `AppRelaunching` and sheet seams. Tests must not launch the real app.
- [ ] `swift build` is warning-free. `scripts/ci-tests.sh fast` exits 0.

## Verification handoff — 2026-10-14

Blocking finding: `KromoraAppDelegate.flushAndReleaseLibrary()` treats the save-failure choice `Quit Without Saving` as a successful release and returns `true`. `ActiveLibraryChooser.offerRelaunch()` interprets `true` as permission to launch the replacement, so `openApplication` is requested after `flushPendingWrites()` failed. The acceptance criterion requires that a failed flush show the existing save-failure choice and not start the replacement process. Change the relaunch failure path so a failed flush cannot authorize a replacement launch, including the discard choice; retain a coherent outcome for the current process. Add a regression test that drives a failed flush through that choice and proves the relauncher is not called.

The lease-order test also only appends `release` from a mocked `releaseLibrary` closure before recording `launch`; it does not inspect the package lease. Extend the regression coverage so the launch request asserts that the old session no longer holds the package writer lease.

To verify, run `swift test --filter ActiveLibrary`, `swift build`, and `scripts/ci-tests.sh fast`; the failure-path test must prove no replacement launch follows a failed flush, and the lease-order test must observe that the package lease is absent when launch is requested.
