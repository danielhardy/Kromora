## Objective

When Reduce Motion is on, workspace changes, filmstrip scrolling, disclosure toggles, and advanced-control reveals must not animate. When it is off, their current animations stay.

## Context

Canvas, crop, and sidebar paths already read `accessibilityReduceMotion`. These do not:

- `ContentView.swift` around lines 281 and 284: `.animation(.easeInOut(...), value: collection.isActive)` and the navigation-mode animation. `chromeAnimation` (around line 315) is the existing nil-when-reduced pattern. Use it or one shared helper.
- `FilmstripView.swift` around line 66: `withAnimation` on selection scroll.
- `InspectorDisclosure.swift` around line 148: expand/collapse. The comment about a single animation source (KRMA-687) still matters; do not add a second overlapping transaction. Gate the one animation.
- `EffectsInspectorView.swift` around line 259: advanced-control reveal.

Search `withAnimation` and `.animation(` under `Sources/KromoraKit/Views`. Switch remaining sites that do not already consult Reduce Motion, or list an exception in the review comment with a reason. Do not change durations. Parent epic: KRMA-994. Review, UI inconsistencies. This is a policy fix, not a claim that motion sickness was observed.

## Acceptance criteria

- [ ] One helper (or the existing `chromeAnimation` pattern) returns nil when Reduce Motion is on and the current animation when it is off. A unit test covers that helper.
- [ ] The four sites above use it.
- [ ] Other view animations found by the search either use it or are listed as exceptions in the review comment.
- [ ] `swift build` is warning-free. `scripts/ci-tests.sh fast` exits 0. Run serial if a UI test you changed is in the serial lane.
