## Objective

Explain the warm-navigation gap with a window-independent breakdown, and propose budgets. Do not change the product and do not rerun the display capture.

## Context

The latest recorded Release evidence is one supervised 30-iteration M1 Pro run, commit `aef050e8`, 16 GB, 60 MP ARW, viewport 2880×1794, cited in `docs/TESTING.md` (measured-state section, around line 642):

- Warm Edit first pixel p95: 286 ms, against a recorded 50 ms target.
- Warm 30-cell grid re-entry p95: 247 ms, against a recorded 100 ms target.
- Main-actor selection before suspension p95: 1.32 ms.
- Warm navigation render admissions: 0, so more GPU work will not explain this interval.

Some presentation timestamps are callback-handler fallbacks. Keep that qualification with the numbers. The 2026-10-11 M4 Pro capture (about 187–197 ms Edit, 154–157 ms grid) used a different method. Do not blend the two.

KRMA-748, KRMA-749, and KRMA-750 closed the 50/100 ms budgets as won't-do. ADR-LKF-001 and `CLAUDE.md` forbid casual capture reruns. KRMA-952 is the human decision to reopen or keep that won't-do. This ticket supplies the evidence that decision needs. Parent epic: KRMA-994. Review finding 7.

## Acceptance criteria

- [ ] A comment on this ticket, and a short addition to the measured-state section of `docs/TESTING.md` or a new `docs/WARM_NAVIGATION_PROFILE.md`, separates view mounting, layout, state publication, frame hydration, and drawable presentation. Use the zero-render warm case so the presentation path is visible without a GPU render.
- [ ] Measurements are window-independent (no `NSWindow`, no `scripts/run-kromora-capture.sh`). Include machine, date, commit, and configuration next to every number.
- [ ] Propose separate targets for first meaningful pixels, usable controls, final-quality settlement, p99 frame gaps, and cancellation under rapid navigation. State what can be asserted in CI and what remains a supervised capture. Do not adopt the targets in code.
- [ ] If the profile shows `document` invalidation rebuilding Light, Color, Effects, and preview together on this path, file one child ticket. If it does not, say so and do not split Observation.
- [ ] No production behavior change. `swift build` stays warning-free if you add an opt-in benchmark. Follow how existing render benchmarks are gated so it does not join the required fast or serial lane.
