## Objective

Make the retouch tests tell shipping quality apart from the stress corpus. A run that expects Heal to fail is not the release gate.

## Context

`docs/RETOUCH.md` reports 8/36 manual Heal, 7/36 Clone, and 5/36 automatic Heal rows inside its limits, and dust-detection fixture recall of 1/12. `RetouchQualityEvaluationTests.testGroundTruthGateReportsCurrentHealAndCloneResults` (`Tests/KromoraKitTests/RetouchQualityEvaluationTests.swift`, around line 101) asserts that Heal fails at least one case in every defect family, and only requires automatic Heal to pass more than zero rows. A real improvement can fail that test. The fixtures are synthetic. Green tests are not camera-quality proof.

Wires and broad removal stay out of v1. Ordinary dust and speck on sky and skin-like backgrounds are in the supported small-defect task. Do not relax thresholds to turn the dashboard green. Do not commit camera originals. KRMA-1004 is the repair work and depends on this gate. Parent epic: KRMA-994. Review finding 8. KRMA-1014 moves this class to the serial lane if it uses Core Image; coordinate so you do not fight that filter edit.

## Acceptance criteria

- [ ] The stress corpus remains, and its current pass/fail counts are reported. The test no longer requires any family to fail.
- [ ] A separate shipping gate names the supported classes (include ordinary dust/speck; exclude wires and broad removal) and fails when a class drops below a floor. Initialize each floor at that class's current passing count so this ticket is not an algorithm change. A later improvement may raise a floor in KRMA-1004.
- [ ] `docs/RETOUCH.md` states which number is the stress report and which is the shipping gate, and that neither is a camera-scale sign-off. Point camera-scale inspection at KRMA-1016.
- [ ] `swift test --filter RetouchQualityEvaluationTests` passes. `scripts/ci-tests.sh fast` or `serial` passes, matching the lane after KRMA-1014 if that has landed; if it has not, leave the class where it is and mention that in the comment.
