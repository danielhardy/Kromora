## Objective

Select All selects every photo that matches the current library query, including photos that are not loaded. Paging and presentation sync must not change that selection. Bulk actions read the authoritative ids.

## Context

Confirmed on 2026-10-14 with a three-photo library and a two-item page. The grid Select All command (`Sources/KromoraKit/Views/KeyboardSurface.swift`, around line 52) calls `ImageCollection.selectAll()` (around line 864), which selects only materialized `filteredItems`. It does not call `PortableLibrarySession.selectAllPortable(query:)` (around line 841) or `LibraryQueryController.selectAll` (around line 724).

The probe selected two loaded items while the package authority still had one selected. The next sync collapsed the collection back to that one id. `AppViewModel.makeBatchExportRequest` (around line 4080) builds work from materialized `collection.selectedItems`, so a cross-page selection cannot be exported, culled, copied, or deleted in full.

KRMA-1012 may cache ordered ids for paging. Do not implement that cache here. Selection intent and page materialization are the whole of this ticket. Parent epic: KRMA-994. Review finding 6.

## Required behavior

- Package-backed grid Select All selects every id in the current query, whether or not its row or thumbnail is loaded.
- A library with no package authority keeps today's loaded-item Select All. Say so in a comment at the branch.
- Loading a page or syncing presentation copies the authoritative selection into the visible rows. It does not drop ids that are not loaded, and it does not add ids the user did not select.
- When the query or filter changes, keep the intersection of the previous selection and the new match set. Do not auto-select new matches.
- Batch export, culling, copy/paste of edits, and deletion iterate the authoritative ids in bounded chunks. They must not decode an image for every selected id in order to know the id list.

## Acceptance criteria

- [ ] The probe is a test: three photos, page size two, one id selected in the package authority, call the same action the responder uses, and both the authority and the collection report three selected ids after sync. No decoded thumbnail is required for the two unloaded ids.
- [ ] A query/filter change drops ids that no longer match and keeps the rest.
- [ ] Reload or a new page does not change the authoritative id set.
- [ ] One bulk path (batch export request construction is enough) uses the full authoritative id list, including an id that is not in `collection.items`, and does not touch that photo's pixel buffer.
- [ ] `swift build` is warning-free. `scripts/ci-tests.sh fast` exits 0.
