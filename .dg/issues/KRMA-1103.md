## Objective

Build the deterministic generator and shared parameter model that every Look in this family is produced from, and ship the first cube (Clean Slide) to prove it end to end.

## Context

Research and parameter table: docs/FILM_SIMULATION_LOOKS_RESEARCH.md (read first). These are best-guess approximations from public qualitative descriptions; there is no reference to verify against, so no acceptance criterion may require matching a camera, a reference photo, or the parameter table within a tolerance. Naming rule: no Fujifilm or film-stock trademarks in Look names, manifest, inspector text, test names, or code identifiers; use the original names from the research doc. Never derive from Fuji JPEG/RAW pairs. Calibrate by eye against the neutral RAW develop of Sony ARW and Apple DNG/HEIC files in the gitignored realworldtest/ folder (Apple/Sony JPEGs already have baked-in looks; secondary check only).

Existing starter cubes in Sources/KromoraKit/Resources/StarterLooks are 3x3x3, too coarse for hue-selective work, and their generator is not in the repo. Parameters per Look: toneCurve (toe, slope, shoulder), globalSaturation, hueSectors (about 12 smoothly interpolated sectors: saturation multiplier and hue shift), chromeDepth (luminance reduction proportional to saturation, warm and blue strengths), shadowTint, highlightTint, skinGuard. Output 33^3 .cube in the editor working color space; check bundle size (about 600 KB per cube as text).

## Acceptance criteria

- A script or test-target tool emits a 33^3 .cube from a parameter value, byte-for-byte reproducible.
- Parameter model, hue-sector interpolation, chromeDepth, tints and skinGuard have unit tests on the generator.
- Clean Slide ships through the manifest with provenance and passes BundledLookTests and manifest validation.
- Tone curve is monotonic, neutral axis stays neutral where intended, and a gray ramp does not clip.
- The generator takes the working space and transfer/encoding as parameters (sRGB today; Display P3 and an extended-range HDR encoding later) and stamps both into each cube's comment header and the manifest notes, so the family can be regenerated for a new space instead of redesigned. Only sRGB cubes are active before KRMA-1121; the P3 release ships P3-authored cubes, without requiring identical prerelease appearance. Cubes are limited to the 0...1 domain.
- Working color space assumption is checked against RenderPipeline and recorded in the manifest notes.
- Per accepted ADR-KRMA-1115, generate in the actual selected authoring space and stamp it; table interpolation uses that stamp independently of the canvas/export target. During preparation only the sRGB set is active. KRMA-1117/KRMA-1121 regenerate/review and activate P3 assets already shipping; if this family lands after the flip, ship P3 from the start. Inputs remain bounded to 0...1. Record encoding, gamut limitations and provenance in generator docs/manifest notes; do not merely relabel sRGB tables as P3.
- docs/LOOKS.md updated; bundle size impact stated.

## Out of scope

Grain, Clarity, DR and white balance recipes. Fidelity to any camera. Other Looks in the family.
