## Objective

Add focused regression coverage proving that resetting the persisted welcome state causes the main window to present onboarding again, and that dismissing/completing that presentation persists completion through the production path.

## Context

KRMA-1049 adds `OnboardingTests.testResetReplaysWelcomeWithoutTouchingOtherDefaults` in `Tests/KromoraKitTests/OnboardingTests.swift`. The test verifies `FirstRunOnboarding.reset(in:)`, but then manually sets `hasSeenWelcome` to `true` while claiming to cover `ContentView.onDismiss`. It would pass if the actual sheet stopped persisting completion or if the startup presentation condition regressed.

## Acceptance criteria

- [ ] A focused test fails if the main-window welcome presentation decision no longer responds to a reset `hasSeenWelcome` value.
- [ ] A focused test covers completion persistence through the same production behavior used when the welcome is dismissed, or documents a concrete limitation and exercises the shared production seam.
- [ ] Coverage remains isolated to onboarding state and does not require importing photos or changing library/settings state.
- [ ] `swift test --filter OnboardingTests` passes.

## Implementation notes

Keep changes localized to onboarding state and its tests. Prefer a small production seam or a deterministic view-level test; do not duplicate the welcome view or introduce broader UI test infrastructure.
