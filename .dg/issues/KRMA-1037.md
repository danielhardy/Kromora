## Objective

Avoid transferring every full Photos original once during review and a second time after confirmation.

## Context

`PhotosImportReviewCoordinator.inspect` calls `transferData` to check membership and file type for
each selection. After confirmation, `PhotosImportCoordinator` calls `transferData` again for each
chosen item. Since KRMA-1031 changed this provider to retrieve the original `PHAssetResource`, large
RAW and iCloud-only assets can incur two full transfers and two temporary-file writes, including
assets the user later deselects.

## Acceptance criteria

- [ ] Review and import do not fetch full original bytes twice for an item that is imported.
- [ ] Cancelling review or deselecting an item does not retain large payloads or leave temporary
      files behind.
- [ ] Provider injection, membership detection, mismatch warning, and the review selection behavior
      remain covered by deterministic tests.
- [ ] A test demonstrates one original-resource transfer for a confirmed item; the transfer strategy
      remains bounded for large RAW batches.
