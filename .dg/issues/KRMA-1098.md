## Objective

Stop computing the durable `editHash`/`renderingHash` on the main actor for every slider tick and every presented frame. Child 1 of the KRMA-954 plan (`docs/RENDER_KEY_PLAN.md`).

## Scope

- `EditDocument.markingManualEdits(from:to:)` (`Sources/KromoraKit/Models/EditDocument.swift`) compares `old.renderingHash != proposed.renderingHash` on every `AppViewModel.updateDocument`. Replace with `==` on the two documents with `lastAutoRunFingerprint` cleared (same semantics, no encoding).
- `AutoWorkflowCoordinator` (`Sources/KromoraKit/Models/PhotoAnalysis/AutoWorkflowCoordinator.swift`) compares `proposed.renderingHash != current.renderingHash`; same replacement.
- `AppViewModel.presentAdjustedFrame` builds `PreviewFrameIdentity(documentHash: request.document.editHash)` for every presented frame. `PreviewFrameIdentity` (`Sources/KromoraKit/Views/PreviewSurface.swift`) is only compared in memory by `PreviewSurface`; carry the document value (or another in-memory structural identity) and compare with `==` instead of the digest.
- Add a golden test pinning `EditDocument.editHash` for a fixed fixture document (with a brush mask, a Look, and an Auto fingerprint that must be excluded), so any accidental change to the durable scheme fails CI.
- Extend `RenderKeyHashingBenchmark` with a `main_actor_tick_ms` line that times one `markingManualEdits` plus one frame-identity construction for each recipe; record it before the change, then after.

## Acceptance criteria

- [ ] No `renderingHash`/`editHash` call remains in `markingManualEdits`, `AutoWorkflowCoordinator`'s change check, or `presentAdjustedFrame`.
- [ ] Large-recipe `main_actor_tick_ms` drops from the ≈ 87.6 ms baseline (two `renderingHash` calls plus one `editHash` per presented frame, 29.204 ms each) to < 0.1 ms.
- [ ] Golden `editHash` test added and passing against the unchanged durable scheme.
- [ ] Existing Auto ownership behavior unchanged: a visible edit still clears `lastAutoRunFingerprint` and marks touched Auto layers user-owned (existing tests stay green; add one for the `==` path if none covers it).

## Rules every change here must keep (KRMA-954)

- [ ] Compute immutable identity once per relevant mutation; never JSON-encode and hash the whole document on every repeated interaction.
- [ ] Session-local caches may use revision or structural keys; durable cross-launch identity keeps a stable digest (`EditDocument.editHash` bytes unchanged — the golden test stays green).
- [ ] Never persist Swift's randomized `Hasher`/`hashValue` output (no file, frame signature, edit revision, report, or string that leaves the process).
- [ ] Do not remove source, Look, or pipeline-version fences (`RenderSourceFingerprint`, Look/LUT content fingerprint, `RenderPipeline.pixelEpoch`, `LocalMaskRenderer.version`, `RenderIdentity.current`, `PresentationFrameEnvelope.storageFormatVersion`).
- [ ] Texture pooling is out of scope (KRMA-963).
- [ ] Report before/after medians from `KROMORA_RENDER_KEY_BENCHMARK=1 swift test -c release --filter RenderKeyHashingBenchmark` for the plain document **and** the large 5-brush recipe, in the handoff comment and in `docs/TESTING.md` (render-key section).
- [ ] A unit test proves equal documents produce equal keys and that an edit to each relevant field changes the key.
- [ ] `scripts/ci-tests.sh fast` and `scripts/ci-tests.sh serial` exit 0.
