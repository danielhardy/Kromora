## Objective

The rule in `KromoraTheme.swift` is that the window-wide copper tint is reserved for things that are **on or selected**. One-shot actions and passive choices should read as ordinary macOS controls. `neutralActionButton()` already applies that rule to some bordered buttons, but many menus, menu pickers, and action buttons still pick up the root `.tint(KromoraTheme.primaryAccent)` from `ContentView.body`, so they render copper even though nothing is active. Audit every inherited-tint control in `Sources/KromoraKit/Views` and make the neutral ones neutral, so copper means "active" everywhere.

## Known instances (from screenshots; the audit must go beyond this list)

- **Culling bar** (Library and Edit filmstrip), `CullingBarView.swift` `LibraryFilterControls`: the `Flag filter` (`All`) and `Rating filter` (`Any rating`) menu pickers.
- **Color inspector → White Balance**, `ColorInspectorView.swift`: the `Menu("Preset")` renders copper. The eyedropper's state-driven tint (copper only while sampling) is correct, so keep it.
- **Masks header**, `MaskingWorkspace.swift` `addMaskMenu`: the `+` / chevron add-mask menu renders copper.
- **Heal → Spots**, `RetouchInspectorView.swift`: the `Overlay` picker (`Auto`) renders copper.
- **Heal → Dust**, `RetouchInspectorView.swift`: the `Detect Dust` action button renders copper. `Accept All` and the other dust and red-eye actions probably have the same issue.

## Context

- Root cause: `ContentView.body` applies `.tint(KromoraTheme.primaryAccent)`, and default `Menu`, `.menu`-style `Picker`, and `Button` controls inherit it. Other sites that need copper set it themselves (`PhotosImportReviewView`, `OnboardingViews`, `RemovableMediaSelectorView`). `ContentView` already resets the tint to `nil` for some toolbar groups (around lines 475 and 598).
- Existing convention, `KromoraTheme.swift` (`extension View`): `neutralActionButton()` gives one-shot actions `.buttonStyle(.bordered).tint(nil)`. Stateful controls use `.bordered` with an explicit state-driven `.tint` (see the culling Pick/Reject, crop aspect toggles, the facet sidebar toggle, and the WB eyedropper).
- Keep the copper where it's intentional: the selected inspector tab, the selected segmented control (for example Heal/Clone), active tool/state toggles, slider fills and thumbs, primary confirmation buttons (`.borderedProminent` in sheets), and the active-facets Filter button.
- Prefer one small shared helper next to `neutralActionButton()` (for example `neutralMenu()` for menus and menu pickers) over scattered `.tint(nil)` calls, so the rule has one obvious home. Decide whether the inherited tint is reset at the control or at a container (inspector section, culling bar). Reset at the narrowest level that still prevents regressions, and keep the root tint so new state controls keep getting copper by default.
- Also check sheets and popovers that inherit the window tint (Look save, Selective Copy, Recipe Extractor, the facet sidebar popover, Settings).
