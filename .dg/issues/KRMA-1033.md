## Objective

Replace the separate single-photo and selected-photo edited-image export entry points with one selection-aware Export experience. The selected photo count determines how many images are exported; the available setup options and behavior stay consistent whether the count is one or many. Keep the interaction direct and familiar, using Lightroom and Darkroom as reference points. This should simplify the File menu, keyboard shortcuts, and export UI.

## Context

- `File > Export…` currently uses ⌘S and opens a save-file panel for the active photo.
- `File > Export Selected Photos…` currently uses ⇧⌘E and opens a folder picker for the explicit Library selection. `MenuCommands.swift`, `KeyboardCommandRouter.swift`, `MenuCommandAvailability.swift`, and `ExportWorkflowCoordinator.swift` own these routes and their selection rules.
- The two paths already share `ExportFormatAccessoryView`, but the batch path adds prefix, suffix, and Append Look naming controls that the single-photo path does not show. The current single path chooses a file; the batch path chooses a folder.
- The shared accessory also contains format, metadata, optional Photos delivery and album, and output-sharpening options. The redesigned single-photo accessory and its shared layout are being handled in KRMA-1024; batch filename prefix/suffix behavior is covered by KRMA-1025.
- Library selection is separate from edit focus. When there is no explicit multi-selection, the active photo is already treated as the one-photo context. Selection-aware request construction lives in `AppViewModel.swift`.
- Export continues to render from each asset's current edit and Look through `ExportCoordinator.swift`; this change is about one user-facing workflow, not changing image rendering or source originals.

## Acceptance criteria

- [ ] Edited-image export has one primary File-menu action and one documented keyboard shortcut. Use the existing ⌘S binding for the unified action and remove the duplicate Export Selected Photos… command and ⇧⌘E binding.
- [ ] The export target is exactly the explicit Library selection when one exists. With no explicit selection, export the active photo as a one-photo job. Never widen a one-photo selection to the whole collection.
- [ ] The setup clearly shows the number of photos that will be exported. One photo and multiple photos use the same destination-selection experience and the same available options, including format, metadata, Photos delivery, output sharpening, and filename prefix/suffix/Look controls.
- [ ] Filename and existing-file handling are consistent for one and many photos. Existing files are never silently overwritten; collisions resolve to a unique output name.
- [ ] The export job renders each selected asset using that asset's edit and Look, reports progress for multi-photo work, and supports cancellation and cleanup without leaving partial output.
- [ ] Menu availability and shortcut help reflect the unified command in Library and Edit contexts, including empty or unavailable selection behavior.
- [ ] Regression coverage verifies one-photo and multi-photo target resolution, shared option mapping, command availability, and the single shortcut. `swift build` is warning-free and `scripts/ci-tests.sh fast` passes; run the serial lane if AppKit/UI tests change.
