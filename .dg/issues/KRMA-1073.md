## Objective

Make opening and leaving a photo from the Library feel like one continuous, reversible transition.

## Context

`ContentView.detailContent` currently switches between separate `LibraryGridView` and editor
subtrees when `NavigationState.mode` changes. A Library cell double-click passes its asset ID to
`AppViewModel.openLibraryImageForEditing(assetID:)`; Edit then composes the canvas, right-side
inspector, and bottom `FilmstripView`. The workspace change currently has a general animation, but
it does not preserve the clicked cell as a foreground image while the editor is introduced.

`FilmstripView` scrolls the selected item to the center when `selectedIndex` changes after it is
mounted. On entry, however, the Library selection is already set before the filmstrip appears, so
that change handler does not guarantee the initial photo is centered. `KeyboardCommandRouter`
currently gives Escape to active crop/retouch/mask cancellation and otherwise leaves the user in
Edit; it should return to Library once no edit submode needs Escape.

Keep the Library grid's layout, scroll offset, filters, and sort stable behind the transition so
nearby thumbnails do not reflow. Preserve existing Escape priority for in-progress tools/drafts and
follow the Reduce Motion behavior already established for workspace and filmstrip animation in
KRMA-1010. KRMA-869 addressed Library-to-Edit loading latency; this ticket is about the visual
handoff and should not add display-bound performance capture requirements.

## Acceptance criteria

- [ ] Double-clicking a Library photo opens that exact asset in Edit and animates its image from
      that cell into the editor canvas, scaling and moving it forward above the grid. Other visible
      grid cells keep their positions and sizes throughout the image transition; no grid reflow or
      scroll jump occurs.
- [ ] After the image has reached the Edit canvas, the right inspector and bottom filmstrip slide
      into place as a second stage of the entrance transition.
- [ ] On the filmstrip's first appearance, its selected photo is centered in the viewport, including
      when the selected photo is the first or last item. Subsequent selection changes continue to
      center the selected thumbnail.
- [ ] In normal Edit mode, an unmodified Escape returns to Library. Existing Escape behavior for
      canceling crop, retouch, mask, or draft interactions keeps priority; once the active submode
      has been dismissed, Escape returns to Library.
- [ ] Returning to Library reverses the entrance: editor chrome slides away and the active photo
      contracts toward its corresponding grid cell while the grid remains stable. Preserve the
      Library scroll offset, filters, sorting, and selection. If the active asset has no usable cell
      in the current grid projection, complete the return without a visual jump or forced grid
      repositioning.
- [ ] Honor Reduce Motion for both directions, using the established non-spatial/immediate behavior
      when enabled.
- [ ] Add focused coverage for asset targeting, initial filmstrip centering (including edge items),
      Escape navigation and tool-cancel priority, and the Reduce Motion path; visually review the
      staged entrance and reverse transition in the app.
