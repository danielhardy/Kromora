## Objective

Bound peak memory while copying large photo selections from the Share sheet.

## Context

`ExportWorkflowCoordinator.copyToPasteboard` renders selected photos serially but retains every
encoded JPEG in an array before writing any of them. Selection count is unbounded, so a large
selection of 4096-pixel images can retain substantial encoded data at once and duplicate it into the
pasteboard server. Preserve the current all-or-nothing clipboard update and multi-image behavior.

## Acceptance criteria

- [x] Measure peak memory for a representative large multi-photo Copy and set a practical bound.
- [x] Reduce peak memory or surface a clear, deterministic limit before silently omitting any
      selected image; retain all-or-nothing behavior for writes that proceed.
- [x] Clipboard contents still contain decodable image bytes after Share closes and the temporary
      export directory is removed.
- [x] Add a deterministic stress/regression test for the chosen bound and run `swift build` plus
      focused Share workflow tests.

## Implementation notes

Preserve clipboard lifetime after the app removes its temporary Share files. Keep work inside the
existing export/share boundary and avoid changing public APIs or persisted data.

## Verification results

Independent verification on 2026-10-19 used Apple Silicon host (large-memory host), macOS 27.2, Xcode 27.0
(27A5252f), a debug build, and the a private local RAW/DNG fixture set in `realworldtest/`. Each selected
photo rendered as a 4096-pixel JPEG through the real engine and pasteboard path. The measurement
test ran in a separate process for each selection size:

| Photos | Peak process footprint | Result |
| ---: | ---: | --- |
| 1 | 3,720.75 MiB | copied |
| 8 | 3,889.35 MiB | copied |
| 24 | 4,373.02 MiB | copied |
| 32 | 4,635.14 MiB | copied |
| 48 | 4,437.30 MiB | rejected |

The measured peak is dominated by one RAW render's Core Image intermediates and does not rise
monotonically with selection size. The 256 MiB production cap bounds the encoded JPEGs retained
across the selection; 32 selected images succeeded, while the larger selection stopped
after crossing the cap. The deterministic production-cap test verifies the previous clipboard
contents remain unchanged on rejection. A Share-picker integration test reads back and decodes the
JPEG items after the temporary Share directory has been removed. This bound applies to the
selection-dependent encoded payload; it does not limit the memory required to render a single RAW.
