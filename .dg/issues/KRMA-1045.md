## Objective

Reassess the edit canvas color-space decision using the reported Apple Silicon host and mirrorless camera sources.

## Context

The user reports that photos from a newer Apple Silicon host and mirrorless camera appear to use a P3 color profile and asks whether the Edit canvas should therefore be P3. Treat the camera/profile observation as something to verify against representative source files; the camera/input profile and the editor’s working/display space are related but are not automatically the same choice.

Today `WorkingSpace.current` is `.sRGB`, and `PreviewSurface` tags the canvas with that same space. KRMA-923 added the matching canvas tag. KRMA-941 previously traced the sRGB preview/export path and recommended deferring a P3 working-space migration because LUT derivation and other color-space-sensitive behavior also require a coherent migration. This new report is a request to revisit that decision with the named camera sources, not permission to flip one color-space constant without evaluating the pipeline.

## Acceptance criteria

- [ ] Inspect representative Apple Silicon host and mirrorless camera source files when available, and record their actual container/RAW type and embedded or declared color profile. Do not infer that a source is Display P3 solely from the camera model or display appearance.
- [ ] Trace how each source profile is decoded/converted into the current working space and how the resulting pixels are tagged for the canvas and export. Distinguish input-profile conversion from working-space gamut and display color management.
- [ ] Determine whether the current sRGB working pipeline clips or otherwise loses visible source colors for the reported inputs. Use a reproducible pixel/profile comparison or documented source-level evidence; do not treat a P3 metadata tag alone as proof that the canvas should be P3.
- [ ] Record a concrete product recommendation: retain the current color-managed sRGB canvas if it preserves intended appearance, or define the P3 migration scope if a real gap exists. Address preview/export agreement, thumbnails, Looks/LUT interpolation and derivation, caches/signatures, and color-profile output where relevant.
- [ ] If the evidence supports implementation, create or propose a scoped follow-up only after documenting the decision and migration boundaries. Do not silently set `WorkingSpace.current` to Display P3 as a standalone fix; HDR/EDR and soft proofing remain separate concerns.
- [ ] Add deterministic coverage for any confirmed input conversion or gamut regression, and verify preview/export profile consistency. Separate these checks from physical display/colorimeter claims; state when hardware validation is unavailable.

## Implementation notes

Start with real embedded profile metadata and the existing image-decoding/render path. Inspect the color-sensitive comments in `WorkingSpace.swift` and `RecipeExtractor.swift` before changing pipeline defaults. The previous Instagram-first sRGB decision in KRMA-941 is important context; explain what the new camera evidence changes before recommending a different product direction.

Related: KRMA-923 (canvas color-space tag), KRMA-941 (sRGB preview/export assessment), and KRMA-994 (release-readiness decisions, including the prior P3 deferral).

Findings (local fixtures in realworldtest/): Apple Silicon host DNG x5 + HEIC and mirrorless camera ARW x2 all report Display P3 via ImageIO/Core Image. For RAW that is the CIRAWFilter develop space, not an embedded ICC profile; the HEIC is 8-bit with a real Display P3 profile and takes the standard (non-RAW) path. Pipeline: source is converted to WorkingSpace.current (sRGB); wide-gamut values survive as extended floats until the final sRGB encode and the [0,1] CIColorCube domain. Measured (800px, P3 render vs sRGB-encoded round trip, scratch scripts, not committed): 1.2-13% of pixels differ >2/255 and 0.02-3.3% differ >8/255; max ~50/255 (saturated HEIC). Out-of-sRGB pixels: ARW 0%, DNG 0-4.4%, HEIC 1.5%. Recommendation: retain the color-managed sRGB canvas for the Instagram-first MVP; a P3 migration must move WorkingSpace.current, derive LUT fitting (RecipeExtractor), LUT interpolation, frame signatures/caches, thumbnails and export tagging together with parity tests. Not done: no colorimeter/hardware validation; no regression test added because no code changed and no regression was confirmed; no follow-up ticket created, since the decision is to defer. Decision recorded in docs/ENGINEERING_GUIDE.md (9720b06a).
