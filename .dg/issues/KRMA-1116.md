## Objective

Thread the working space through every cache key, signature and identity so a space change can never reuse a stale render. No visible change.

## Context

Part of the Display P3 epic KRMA-1114 (read its Context first). Until the final flip ticket lands, WorkingSpace.current stays .sRGB and this ticket must be behavior-neutral: sRGB renders, exports and cache behavior stay identical, and existing tests pass. Zero-opt-out Swift 6 rules apply (see CLAUDE.md). Run the deterministic lanes (scripts/ci-tests.sh fast, then serial for Core Image tests), not the display-bound capture harness.

Look at RenderCacheKey, RenderRequest, RenderEngine/RenderEngineResources (render caches), LUTFilterCache, PresentationFrame and the preview frame signature/store, and ThumbnailFrameEncoding. Today they read WorkingSpace.current implicitly.

## Acceptance criteria

- Each cache or signature above includes the space as an explicit component (or is shown by test not to need it, with the reason recorded in a code comment).
- A test renders the same document in .sRGB and .displayP3 (constructed explicitly, not by flipping .current) and asserts the caches and frame signatures do not collide.
- sRGB output is byte-identical to before for existing render and thumbnail tests.

## Out of scope

Changing WorkingSpace.current, export tagging, Looks, Auto.
