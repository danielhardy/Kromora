## Objective

Make Kromora's current documentation read as one shipping product. A reader should learn who the app is for, what it does, what it leaves out, and which guide owns each contract, without a second essay that restates the README.

## Context

KRMA-669 made `docs/PRODUCT_SCOPE.md` the MVP intent source and `docs/DOCUMENTATION_AUDIT.md` the map. The README now carries the audience, the Library → Edit → Export loop, current capabilities, and the limits. `PRODUCT_SCOPE.md` repeats that material and then defers to the guides that already own the contracts. The sentences that are still unique belong in those guides:

- The release bar (honest partial failure, one render pipeline, disposable caches, which verification lanes count) belongs in `docs/TESTING.md`. That guide already claims the lanes and currently points the bar back at `PRODUCT_SCOPE.md`.
- Sharper exclusions (Finder double-click and the unwired backup/restore types, proofing/print/HDR, embedded depth, metadata round-tripping, and no Lightroom parity) belong in the README limits. Quit-and-copy and the virtual-copy disk cost are already in `docs/STORAGE_POLICY.md` and the README.
- The "which document is authoritative" paragraph belongs only in `docs/DOCUMENTATION_AUDIT.md`.

Current guides and contributor docs link `PRODUCT_SCOPE.md`, including `CLAUDE.md`, `README.md`, `ENGINEERING_GUIDE.md`, `APP_ARCHITECTURE.md`, `TESTING.md`, `STORAGE_POLICY.md`, `RETOUCH.md`, `AUTO_EXPOSURE_POLICY.md`, `COMPARISON_MODE.md`, `INTEROP_EXPORT.md`, `AUTO_PERFORMANCE.md`, `LIBRARY_PACKAGE_BASELINE.md`, and `docs/APP_STORE_SUBMISSION.md`. Submission answers cite it as evidence of product scope. After it is retired, each citation must point at the README or the guide that now holds the fact.

The documentation map is dated 2026-10-12 and does not list three files that are in `docs/` today:

- `docs/APP_VIEWMODEL_OBSERVATION_PLAN.md` is a completed migration plan written as a ticket sequence. The engineering guide already states the Observation rules.
- `docs/EDITOR_SESSION_RETENTION.md` mixes a KRMA-1059/1060 decision record with the live retention contract (32 sessions, 192 MiB, pin and eviction rules).
- `docs/KEYBOARD_QA_CHECKLIST.md` is a 2026-10-13 hands-on log. Its shortcut table stays in agreement with `KeyboardShortcutCatalogTests`; the narrative around it is a spot-check record.

`.context/` also holds reviews newer than the map (`2026-10-13`, `2026-10-14`, `2026-10-15`, `2026-10-19`) plus `initial_concept.md` and the deferred iCloud plan. The map's retention rule is to delete superseded one-off reviews. Those reviews are not current product intent.
