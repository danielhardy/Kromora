## Objective

Correct `dg issue show --json` dependency resolution for issues whose dependency records are present in the selected project's index and issue files.

## Context

With `dg` 0.3.0+046b9b5, `dg issue show KRMA-1063 --json` reports KRMA-1062 and KRMA-1054 as missing, and `dg issue show KRMA-1062 --json` reports KRMA-1061 as missing. All four issues are present and done in `.dg/.project/index.json` and under `.dg/issues/`; `dg validate` succeeds. `dg blockers` does not report these completed issues as dependency-blocked. KRMA-980 has the same class of false missing-dependency output for KRMA-979.

This appears to be a DispatchGraph CLI resolver issue, not malformed project data. Keep the dependency relationships and historical verification reports intact while the CLI owner corrects the resolver.

## Acceptance criteria

- [ ] `dg issue show --json` resolves dependencies using the same project root and indexed issue records used to load the requested issue; completed dependencies are not reported as missing.
- [ ] `dg issue show KRMA-1062 --json` and `dg issue show KRMA-1063 --json` report the existing done dependencies correctly and no false `dependency_blocked` state.
- [ ] A genuinely unresolved dependency remains reported as unresolved (for example KRMA-1076's dependency on KRMA-1086 while KRMA-1086 is blocked).
- [ ] `dg validate` still succeeds, `dg blockers` still reports genuine blockers, and no retouch verdicts or dependency records are changed to hide the resolver defect.

## Implementation notes

Owner: DispatchGraph CLI maintainers. Remediation: fix or upgrade the `dg issue show` dependency resolver, then rerun the issue-show reproductions and compare them with `dg validate` and `dg blockers`. Until that is available, trust the indexed issue records plus `dg validate`/`dg blockers` for dependency state; treat `blocked` and `dependency_blocked` from `dg issue show --json` as unreliable for issues with `depends_on`.
