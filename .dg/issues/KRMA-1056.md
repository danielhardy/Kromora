## Objective

Make the PhotosReviewTransferCacheTests fixture compile without crossing main-actor state from nonisolated XCTest lifecycle overrides.

## Context and reproduction

Finding 5, isolated code-fix slice. The October 19 warning-gate build emitted two diagnostics in PhotosReviewTransferCacheTests.swift: setUpWithError mutates the main-actor directory property, and tearDown reads it from a nonisolated context. The class is @MainActor but the inherited XCTest hooks do not acquire that isolation. The command still exited 0; enforcement is tracked separately in KRMA-1057.

The tests cover retained transfer limits, single-fetch reuse, cancellation, and cleanup for Photos review. Preserve those assertions and unique temporary-directory lifetime. Do not change production Photos import to solve a test fixture warning.

Source review: .context/2026-10-19-release-readiness-review.md (reviewed bb01e0c374fb; re-read current code because subsequent work may have landed).

## Acceptance criteria

- [ ] Move fixture setup/cleanup to a Swift 6-safe ownership pattern, such as actor-isolated per-test setup and defer, or an existing suitable test helper; no unsafe isolation annotations, casts, or suppressed diagnostics.
- [ ] Each test uses a unique disposable directory, and cleanup runs after any suspended cache/transfer work has settled on both success and failure.
- [ ] Retain all transfer count, byte-limit, cancel/discard, and cache-consumption assertions.
- [ ] The focused suite and a recompiled warning-gate output contain neither of the reported isolation warnings.
