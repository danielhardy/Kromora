## Objective

Make Looks independent of the app working space: each CubeLUT knows the space it was authored in and is interpolated in it, so flipping the app to P3 does not change how any existing Look renders.

## Context

Part of the Display P3 epic KRMA-1114 (read its Context first). Until the final flip ticket lands, WorkingSpace.current stays .sRGB and this ticket must be behavior-neutral: sRGB renders, exports and cache behavior stay identical, and existing tests pass. Zero-opt-out Swift 6 rules apply (see CLAUDE.md). Run the deterministic lanes (scripts/ci-tests.sh fast, then serial for Core Image tests), not the display-bound capture harness.

CubeLUT.makeFilter currently passes WorkingSpace.current as inputColorSpace. Touch CubeLUT (parse an optional authoring-space comment header, default sRGB when absent), LUTFilterCache, BundledLookLibrary manifest notes, LookLUTConverter (Save as Look writes a cube; stamp it with the space it was sampled in), RecipeExtractor (derive is pinned to .sRGB; stamp derived cubes sRGB) and EmbeddedLookLoader/package round trips (bytes keep the header). Follow the policy decision ticket's Look approach.

## Acceptance criteria

- Parser reads and writes the authoring-space header; unknown or missing means sRGB; malformed values fail with a clear error.
- makeFilter and the filter cache key use the cube's authoring space, not WorkingSpace.current.
- Save as Look and Derive stamp the correct space; existing bundled, user and embedded Looks parse unchanged.
- Tests: a Look with no header renders identically before and after; a P3-stamped cube round-trips through Save/embed/load; cache keys differ by space.
- docs/LOOKS.md documents the header.

## Out of scope

Flipping WorkingSpace.current. Converting existing Looks.
