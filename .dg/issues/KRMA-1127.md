## Objective

Agents were running bare `swift test` or whole `ci-tests.sh` lanes after every edit. The suite is about 2,900 tests (2,062 fast, 744 serial, 63 optional) and `ci-tests.sh` runs `swift test list` first, which needs a full test-target build. Give agents a cheap, targeted inner loop and a written policy for when to run what.

## Acceptance criteria

- `scripts/test-affected.sh` maps changed files under `Sources/` and `Tests/` to the covering XCTest suites and runs `swift test --filter` on only those.
- Benchmark, performance, and optional-lane suites are never selected automatically.
- `--list`, `--wide`, `--base <ref>`, and explicit `Suite[/testMethod]` arguments work.
- `CLAUDE.md` states when agents run the affected set, a lane, or leave tests to CI.

## Follow-ups (not in this ticket)

- Time every serial suite, then split slow suites into a separate lane.
- Replace the serial_filter regex with per-suite lane declarations so the lane audit does not need a full build.
- Move model/coordinator tests off the real RenderEngine onto FakeRenderEngine where possible.
- Consider Swift Testing with tags for new suites only. A wholesale migration is not worth it: the serial lane exists because of shared GPU/AppKit state.
