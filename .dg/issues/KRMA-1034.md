## Objective

When the user clicks the toolbar Share/Export button, present the macOS sharing picker next to that button. It currently appears at the side of the window instead of being anchored to the control.

## Context

- The toolbar action is in `Sources/KromoraKit/Views/ContentView.swift` (the Export button with the share symbol). It attaches `ShareAnchorView` as a background.
- `Sources/KromoraKit/Views/ShareAnchorView.swift` registers an invisible AppKit view with `ExportWorkflowCoordinator`.
- `Sources/KromoraKit/ViewModels/ExportWorkflowCoordinator.swift` calls `NSSharingServicePicker.show(relativeTo:of:preferredEdge:)` using the registered anchor when it is attached to a window, then falls back to the key/main window content view when no valid anchor is available.
- KRMA-1023 fixed a picker that could fail to present when toolbar copies moved between windows. Its lifecycle regression coverage verifies which view is passed to the presenter, but the reported issue here is the visible picker position: it opens at the side of the window rather than at the button.
- Share supports both the active single photo and a multi-photo Library selection through the same toolbar button and coordinator.

## Acceptance criteria

- [ ] Clicking the toolbar Share/Export button presents the sharing picker anchored to the actual button bounds, with the picker positioned next to the button instead of the window edge.
- [ ] Correct placement holds for single-photo and multi-photo Share, in both Library and Edit workspaces, including after switching workspaces or rebuilding toolbar content.
- [ ] When the toolbar button is attached to a window, presentation uses an anchor whose bounds identify the button location; a window content view is used only when the button anchor is genuinely unavailable.
- [ ] Regression coverage checks the anchor view and its positioning data passed to the picker presenter. Verify the native picker placement in the running app and record the result.
- [ ] `swift build` is warning-free and `scripts/ci-tests.sh fast` passes; run the serial lane if AppKit/UI tests change.
