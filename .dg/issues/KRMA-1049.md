## Objective

As a user, I can reset and replay the first-run welcome experience from Settings so I can revisit onboarding after setup.

## Context

KRMA-619 delivered the existing welcome flow and Library/Edit/Export tour, which are also described in docs/ONBOARDING.md. ContentView persists welcome completion in the hasSeenWelcome setting and presents the welcome at startup only when it is false. Settings currently has no way to reset that state. Resetting onboarding must not repeat one-time setup actions such as importing the bundled sample photos.

## Acceptance criteria

- [ ] Settings provides a discoverable, clearly labeled action to reset the first-run experience and explains that it will appear the next time the main app opens.
- [ ] After reset, the existing welcome flow appears on the next app launch, and its current import and tour choices continue to work.
- [ ] Dismissing or completing the replayed welcome persists completion again, so it does not return on every launch.
- [ ] Resetting onboarding does not alter library contents, edit revisions, or unrelated Settings values, and does not automatically import sample photos again.
- [ ] Add focused regression coverage for resetting and replaying the welcome flow, and update docs/ONBOARDING.md with the Settings entry point.

## Implementation notes

Reuse the existing onboarding presentation and persisted completion state introduced in KRMA-619. Keep the reset scoped to onboarding state; do not duplicate the welcome or tour views or clear unrelated preferences.
