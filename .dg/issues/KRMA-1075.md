## Objective

Let Settings > Choose Library select a valid `.kromoralibrary` package through the normal file picker.

## Context

Observed while preparing KRMA-1063 on the ad hoc packaged build `116f14fddaa4`, macOS 27.2:
Settings > Choose Library displayed the valid `Retouch Review.kromoralibrary` package disabled.
Navigating directly to its path still did not allow selecting it. After quitting all package writers,
renaming that disposable package directory to `Retouch Review Library` made it selectable; validation,
relaunch, and all 27 stored photos worked. The package's contents did not change.

`ActiveLibraryChooser.choose` uses the generic folder chooser. `AppKitFileDialogAdapter.chooseFolder`
sets `canChooseFiles = false` and `canChooseDirectories = true`, without a package-specific selection
contract. Investigate AppKit package handling and add a focused library chooser rather than weakening
every generic folder dialog. The rename was a qualification workaround, not the proposed product UX.

## Acceptance criteria

- [ ] A valid `.kromoralibrary` package is selectable in Settings and passes the existing structural validation.
- [ ] Choosing it and relaunching opens its photos and saved edits; switching back to Default Library works.
- [ ] Invalid packages remain rejected with the existing useful error. Generic import/destination folder pickers keep their own folder semantics.
- [ ] Add focused dialog-configuration coverage and run applicable tests plus `scripts/app-store-build.sh`; record a live picker check using a disposable package.

## Implementation notes

Read `CLAUDE.md` and `.dg/AGENTS.md`, claim this issue before changing product code, and preserve
the active personal library. The local qualification package is ignored under
`.build/krma1063-evidence/Retouch Review Library`. Do not commit or upload its photographs.
