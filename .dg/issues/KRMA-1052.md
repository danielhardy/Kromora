## Objective

Make opening or recovering a malformed library fail without modifying canonical package data or unrelated files.

## Context and reproduction

Finding 2 of the October 19 review was reproduced through PortablePackageOpener.openBlocking and confirmed expired-writer takeover. recover(at:) decodes a journal, then removes packageRoot.appendingPathComponent(journal.stagingDirectory) without checking the expected transaction directory. rollback also constructs absolute URLs directly from backupPath. Normal PackagePath containment is bypassed.

Disposable reproduction: create a valid package and an expendable sibling directory containing a sentinel; write a committed journal with no files and stagingDirectory set to ../UnrelatedSibling; install an already-expired lease; open using PortablePackageOpener.openBlocking(asynchronousIndexLoading: true, confirmTakeover: { _ in true }). The opener succeeds and deletes the sibling. All fixtures must live under one generated temporary root. The standalone probe at /tmp/kromora-release-review-probe.swift is optional evidence, not a required permanent fixture.

Containment alone is insufficient: stagingDirectory = Assets is contained but must never be accepted as cleanup staging. Current valid journals store some backup paths as absolute paths; blindly rejecting every absolute backup would break recovery of the app's own existing journals.

Source review: .context/2026-10-19-release-readiness-review.md (reviewed bb01e0c374fb; re-read current code because subsequent work may have landed).

## Acceptance criteria

- [ ] Add a failing deterministic reproduction through the production opener; an outside sentinel and canonical package Assets remain byte-for-byte intact.
- [ ] Validate the entire journal before the first journal-directed replay/cleanup mutation, while recovery holds the correct ownership fence: journal/transaction identity, expected Recovery/Staging/<transaction-id> ownership, every staged/backup/move/removal path, and any applicable package identity.
- [ ] Reject traversal, absolute cleanup paths, canonical-data cleanup targets, mismatched transaction directories, and symlink escapes. Backup paths emitted by the current valid writer recover successfully after validation.
- [ ] Apply containment to the Recovery directory roots and enumerated journals too; checking only leaf strings must not allow a symlinked recovery root to direct cleanup elsewhere.
- [ ] Malformed journals produce an actionable error and retain recovery evidence; do not report successful recovery or clear the writer state after rejection.
- [ ] Keep ownership fencing, live-writer refusal, valid interrupted-commit recovery, and existing valid-package tests passing.

## Implementation boundaries

This is a logical package-boundary defect within existing filesystem permissions, not a macOS sandbox escape. Reuse PackagePath and narrow validation helpers; do not add a generic filesystem framework. The separate rollback-idempotency ticket follows this change because both touch journal representation.

Read CLAUDE.md and .dg/AGENTS.md first. Target macOS 26+ / Apple Silicon only, Apple frameworks only, Swift 6 without unsafe isolation escape hatches. Preserve unrelated working-tree changes and existing claims. Claim this issue before implementation; work one issue at a time. Verify only the applicable focused/CI lanes; do not run scripts/run-kromora-capture.sh for an ordinary fix or to obtain a new timing number. Use generated/disposable fixtures and never modify a user's active library. Hand off implementation at review through the normal DispatchGraph workflow; do not claim unrun hands-on checks passed.
