## Objective

Let users identify and re-import assets whose stored filename extensions disagree with their bytes.

## Context

KRMA-1031 records the re-import policy for mismatched files imported before validation, but the
implementation does not scan or list those existing package originals. A user who already has a
file such as `DSC00160.ARW` containing JPEG bytes cannot find it through a Kromora diagnostic.

## Acceptance criteria

- [ ] A package diagnostic lists originals whose bytes are positively identified as incompatible
      with their stored filename extension, including RAW extensions over known non-RAW data.
- [ ] The diagnostic identifies the affected library asset and provides a clear path to re-import
      from Photos.
- [ ] The feature never rewrites or deletes stored originals automatically.
- [ ] Generated fixtures and a temporary package verify the listing and re-import guidance without
      requiring real Photos assets; `swift build` and the relevant CI lane pass.

## Implementation notes

Keep the diagnostic read-only. Reuse the byte/type detection policy from KRMA-1031 and avoid opening
or hashing more package data than the diagnostic requires.
