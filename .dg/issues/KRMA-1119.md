## Objective

Make the editing canvas, thumbnails and histogram correct for a non-sRGB working space, so the flip changes the displayed gamut and nothing else.

## Context

Part of the Display P3 epic KRMA-1114 (read its Context first). Until the final flip ticket lands, WorkingSpace.current stays .sRGB and this ticket must be behavior-neutral: sRGB renders, exports and cache behavior stay identical, and existing tests pass. Zero-opt-out Swift 6 rules apply (see CLAUDE.md). Run the deterministic lanes (scripts/ci-tests.sh fast, then serial for Core Image tests), not the display-bound capture harness.

Touch PreviewSurface (MTKView colorspace tag), PresentationFrame, PreviewPresentationCoordinator and PreviewAdmissionCoordinator, ThumbnailFrameEncoding, RenderEngine+Histogram, MaskInteractionPresentationBridge, MaskingWorkspace and the Metal presentation sources. Check any place that assumes sRGB-encoded 8-bit values (histogram bins, mask overlays, thumbnail encoders).

## Acceptance criteria

- With the space constructed explicitly as .displayP3 in tests, canvas tag, thumbnails and histogram are produced in P3 and match a direct Core Image P3 render within the existing parity tolerance.
- sRGB behavior is byte-identical to before.
- Histogram bins and mask overlays are verified against known P3 test patches.
- No display-bound capture run is required.

## Out of scope

Export, Looks, Auto.
