## Objective

Add native contextual actions to photo thumbnails in the Library grid and Edit filmstrip, so common
photo and edit operations are available directly from the image under the pointer.

## Context

There is currently no `.contextMenu` in `Sources/KromoraKit`. The Library grid uses a click surface
for selection/open, and filmstrip thumbnails are buttons; users must find image actions in the
toolbar, culling controls, or menu bar instead of acting on the photo they clicked.

Kromora already has owners for most requested operations. Reuse these paths rather than duplicating
business logic:

- `EditClipboardCoordinator` and `AppViewModel` copy/paste edit settings, including selective and
  batch paste behavior. The edit clipboard is Kromora's in-app edit-settings clipboard.
- `ExportWorkflowCoordinator.copyToPasteboard` copies rendered image output to the system clipboard.
  A context action must copy the developed output, not the small library/filmstrip thumbnail.
- `AppViewModel.createVirtualCopy` and `PortableLibrarySession.createVirtualCopy` create an
  independent copy for a managed library photo. Per `docs/PRODUCT_SCOPE.md`, each virtual copy
  stores its own full copy of the original, so it consumes the original's storage size again.
- `LibraryBrowsingCoordinator` owns flags, ratings, and confirmed library removal. Preserve the
  existing delete confirmation and managed-original Trash behavior.
- `MenuCommands.swift` already exposes several of these operations from the menu bar. Keep menu
  enablement and contextual action availability consistent.

The context menu should cover the photo under the pointer and cooperate with existing multi-select
behavior. Define its target semantics explicitly: right-clicking a photo outside the current
selection makes it the sole focused/selected photo; right-clicking a photo already in a selection
preserves the selection. The context menu itself must not open the photo or perform an action.

Include these useful actions where applicable: Open in Edit; Copy Image; Copy Edit Settings; Paste
Edit Settings; Duplicate / Create Virtual Copy; flag as Pick, Reject, or Clear Flag; set/clear star
rating; Export/Share; and Delete from Library. Actions that operate on multiple photos should use
the resolved selection. Copy Edit Settings is a single-source operation and uses the photo under
the pointer. Duplicate creates a virtual copy of the photo under the pointer and must be clearly
identified as such; do not imply it is a storage-free alias.

Likely implementation surfaces are `LibraryGridView.swift`, `FilmstripView.swift`, their thumbnail
views, `MenuCommands.swift`, and focused workflow/coordinator entry points. The project targets
macOS 26+ and Swift 6 with Apple frameworks only.

## Acceptance criteria

- [ ] A native context menu can be opened on a photo thumbnail in both the Library grid and Edit
      filmstrip, including through standard keyboard/accessibility context-menu invocation where
      supported by the control.
- [ ] Right-clicking an unselected photo makes it the sole focused/selected target before the menu
      actions are resolved. Right-clicking a photo already in a multi-selection preserves that
      selection. Opening/canceling the menu never opens the photo or changes it beyond this target
      selection behavior.
- [ ] The menu provides Open in Edit, Copy Image, Copy Edit Settings, Paste Edit Settings, Duplicate
      / Create Virtual Copy, Pick/Reject/Clear Flag, star rating/clear rating, Export/Share, and
      Delete from Library, with labels and enabled state appropriate to the target and library.
- [ ] Copy Image copies the developed/rendered output for the context photo or selected photos, not
      a thumbnail. Copy Edit Settings reads the photo under the pointer as its source. Paste Edit
      Settings is disabled without a valid edit clipboard payload and pastes to the selected set (or
      the context photo when it is the only target), using existing RAW/category compatibility and
      persistence behavior.
- [ ] Duplicate / Create Virtual Copy operates on the photo under the pointer, is available only
      when that photo belongs to a managed package library, creates an independent asset with the
      source photo's edits, and leaves the source unchanged.
- [ ] Pick/Reject/Clear Flag, rating changes, Export/Share, and Delete use the resolved context
      target or selection consistently. Delete presents the existing confirmation before removal
      and preserves current Trash/partial-failure behavior.
- [ ] Unavailable actions are disabled or omitted with a clear reason; choosing any enabled action
      performs it on the intended target(s), reports failures through existing UI feedback, and
      never silently acts on a different active photo.
- [ ] Add tests for context-target selection semantics, target resolution, menu availability, and
      routing each action to the existing workflow. Include single-photo, right-click-within-a
      multi-selection, right-click-outside-selection, no-edit-clipboard, and non-package duplicate
      cases.
- [ ] Manually verify both surfaces with single and multiple selections, including copy/paste,
      duplication, flags/ratings, and confirmed deletion. Verify context-click does not interfere
      with double-click-to-open, ordinary selection modifiers, or keyboard navigation.
- [ ] `swift build` remains warning-free under Swift 6 mode, with no third-party dependencies or
      compatibility branches; run the relevant deterministic and UI test lanes for the touched
      workflows.

## Implementation notes

Keep contextual-menu state and action targets value-based and short-lived; don't add a second
selection model or a second edit clipboard. Resolve the target at action delivery time because
windowed library pages can change while menus are open. Route mutations through the existing library,
edit clipboard, export, and deletion owners so edits persist, stale asynchronous work stays fenced,
and multi-photo partial failures remain reported honestly.
