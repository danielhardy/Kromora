## Objective

Library facet counts must refresh when the index changes and must never publish results from a cancelled or superseded query.

## Context

Source: audit `.context/audits/2026-11-03-code-quality-audit.md` (against `b7e46d5c`); probe source and outputs are in `.context/audits/evidence/2026-11-03/README.md`. Line numbers below are from that commit and may drift.

`LibraryFacetSidebar` (`Views/LibraryFacetSidebar.swift:75`) refreshes counts with `.task(id: query)`. Imports and metadata backfills change the index but leave the query equal, so counts go stale. The task also assigns its result unconditionally after awaiting the off-main computation, so a cancelled older task can still publish old counts. Code-confirmed.

## Acceptance criteria

- [ ] Counts are keyed to query plus a published index generation; rapid index changes are coalesced.
- [ ] Results are assigned only if the task is not cancelled and the captured query/generation is still current.
- [ ] One coherent count snapshot is published (categorical counts, numeric bounds, and unavailable-metadata messages update together), not recomputed in view getters.
- [ ] Tests: import while the sidebar is open; metadata backfill completing with no filter change; old and new requests completing in reverse order.
