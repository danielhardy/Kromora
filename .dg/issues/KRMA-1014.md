## Objective

Tests that use Core Image or the real render engine must run in the serial lane. The fast lane stays deterministic and parallel-safe.

## Context

`scripts/ci-tests.sh` puts a test in the fast lane unless its class is named by `serial_filter` or `optional_filter`. The 2026-10-14 review found `RetouchQualityEvaluationTests` and real-render Auto tests in the fast lane even though they use Core Image. The discovery check only proves the three filters partition every test name. It does not prove the fast lane is free of shared GPU or Core Image state.

`docs/TESTING.md` describes the lanes. Parent epic: KRMA-994. KRMA-1003 edits `RetouchQualityEvaluationTests`; if both are in flight, keep the class name stable so the filter still matches.

## Acceptance criteria

- [ ] Inventory fast-lane classes that construct a `CIContext` or call the production `RenderEngine` rather than `FakeRenderEngine`. Start with `RetouchQualityEvaluationTests` and the Auto tests. Record the list in the review comment.
- [ ] Add those class names to `serial_filter`. Do not move fake-engine or pure model tests.
- [ ] `scripts/ci-tests.sh` lane discovery still reports `fast + serial + optional == total`.
- [ ] `scripts/ci-tests.sh fast` and `scripts/ci-tests.sh serial` exit 0.
- [ ] A short comment above `serial_filter` states that real Core Image and real-engine classes belong there.
