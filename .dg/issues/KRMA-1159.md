## Objective

Charge each resident edit session for the history it actually retains, so eviction honors the byte budget.

## Context

Source: audit `.context/audits/2026-11-03-code-quality-audit.md` (against `b7e46d5c`); probe source and outputs are in `.context/audits/evidence/2026-11-03/README.md`. Line numbers below are from that commit and may drift.

`EditorDocumentCoordinator.Entry.cost` (`ViewModels/EditorDocumentCoordinator.swift:30`) is `(1 + undo + redo) * documentCost`, using only the *current* document's cost. Older undo/redo documents can be much larger (for example removing a heavy brush mask leaves a small current document and a large retained one).

Probe with the production estimator: commit a brush-heavy document, remove the mask, make the session inactive, request eviction under a 1 MB budget: `byteBudget=1000000 reported=8192 sumOfRetainedDocumentEstimates=3208581 retainedSessions=1`. The 3.2 MB figure sums the same production estimator over retained documents; it is not RSS. Copy-on-write may reduce real allocations, but a large retained value is not free.

## Acceptance criteria

- [ ] Session cost is the sum of cached per-entry costs across the current document, undo stack, redo stack, and any open gesture group; costs are updated when entries move between stacks.
- [ ] Aggregation uses saturating arithmetic.
- [ ] Active, dirty, and pinned sessions remain intentionally exempt from eviction; the inactive clean-session case in the probe is evicted when over budget.
- [ ] Tests: large -> small -> Undo -> Redo; histories mixing payload sizes; group cancel; eligibility/eviction asserted against the sum of retained estimates.
- [ ] Existing `EditDocumentRetentionCostTests` pass.

## Implementation notes

- Keep per-entry cost caching cheap; do not re-estimate whole histories on every edit.
- Release RSS plateau over a long session is a separate measurement, not required for this ticket.
