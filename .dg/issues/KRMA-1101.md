## Objective

Replace the per-request `RenderCacheHash.digest` calls on the render path with fields of the memoized `RenderDocumentIdentity`. Child 4 of the KRMA-954 plan (`docs/RENDER_KEY_PLAN.md`); depends on the identity/memo ticket.

## Scope

- Build the identity once at request entry in `RenderEngine` and thread it through `RenderBuildPlan` (replacing `maskIdentity`/`documentIdentity` digests and the revision ledger inputs), `previewCacheKey`, `DevelopedSourceCacheKey` (`developHash`, standard and RAW paths, plus the RAW `OutputKey`), `ProcessingPrefixCacheKey` (`developHash`, `upstreamHash`, `localAdjustmentsHash`), `LocalMaskCacheKey.definitionHash` in mask resolution and composition, `MaskRasterCacheIdentity.payloadVersion`, and the definition-hash checks in `LocalMaskRendering.swift`.
- Pass each component's memoized definition digest in `LocalMaskResolveRequest`; default and semantic resolvers use it for `LocalMaskPayload.definitionHash` and validation instead of hashing the source again.
- Keep every existing fence field in each key (`RenderSourceFingerprint`, LUT `cacheFingerprint`, `RenderPipeline.pixelEpoch`, `LocalMaskRenderer.version`, scale/ROI/space/quality).
- These keys are session-only; no persisted format changes.

## Acceptance criteria

- [ ] `RenderKeyHashingBenchmark` `warm_digest_ms_per_request` on the large recipe drops from 173.573 ms (baseline) to < 1 ms after an exposure tick; plain document does not regress (≤ 0.153 ms). Report the first cache-miss digest number too. Update the benchmark's mirrored digest set to the new call sites so the number stays honest.
- [ ] Existing render cache, mask cache, prefix, revision-ledger, and semantic-mask supersession tests stay green; add a test that an exposure-only tick reuses mask payload and developed-source entries and that a brush, Look, crop, retouch, or RAW-develop edit misses the right caches.
- [ ] No remaining `RenderCacheHash.digest(document...)`, `digest(rawDevelop)`, `digest(localAdjustments)`, or `digest(component.source)` call in `RenderEngine.swift` or `LocalMaskRendering.swift`.

## Rules every change here must keep (KRMA-954)

- [ ] Compute immutable identity once per relevant mutation; never JSON-encode and hash the whole document on every repeated interaction.
- [ ] Session-local caches may use revision or structural keys; durable cross-launch identity keeps a stable digest (`EditDocument.editHash` bytes unchanged — the golden test stays green).
- [ ] Never persist Swift's randomized `Hasher`/`hashValue` output (no file, frame signature, edit revision, report, or string that leaves the process).
- [ ] Do not remove source, Look, or pipeline-version fences (`RenderSourceFingerprint`, Look/LUT content fingerprint, `RenderPipeline.pixelEpoch`, `LocalMaskRenderer.version`, `RenderIdentity.current`, `PresentationFrameEnvelope.storageFormatVersion`).
- [ ] Texture pooling is out of scope (KRMA-963).
- [ ] Report before/after medians from `KROMORA_RENDER_KEY_BENCHMARK=1 swift test -c release --filter RenderKeyHashingBenchmark` for the plain document **and** the large 5-brush recipe, in the handoff comment and in `docs/TESTING.md` (render-key section).
- [ ] A unit test proves equal documents produce equal keys and that an edit to each relevant field changes the key.
- [ ] `scripts/ci-tests.sh fast` and `scripts/ci-tests.sh serial` exit 0.
