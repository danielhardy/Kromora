## Objective

Make the macOS Share sheet’s Copy action place usable image data on the clipboard.

## Context

In the current Share flow, selecting the system share-sheet action named “Copy” does not appear to make the photo pasteable into Slack or a chat composer. The expected result is that the rendered image itself is available from the general pasteboard for a later paste, rather than only a temporary file path, file URL, or filename.

The current workflow builds rendered share files and supplies file-based items to `NSSharingServicePicker`; `SharePickerDelegate` owns their lifetime until the selected service finishes or the picker is dismissed. Trace what the Copy service actually writes to `NSPasteboard` and whether deleting the temporary share file after completion invalidates the copied representation. KRMA-949/989 define the size, format fallback, and rendered-content policy for Share; preserve those semantics.

## Acceptance criteria

- [ ] Reproduce Copy from the current Share flow and inspect the resulting general-pasteboard types and values. Record whether the current behavior copies a file reference, URL, or image representation.
- [ ] After choosing Copy for one photo, a paste destination that accepts images (for example Slack or a chat composer) receives the rendered, edited image pixels without requiring the user to open or locate an exported file.
- [ ] The pasteboard advertises a supported image type and contains decodable image bytes; it is not only a file URL, path, or display name. The copied image retains the edit/Look, expected share dimensions/quality, and its encoded color profile.
- [ ] Clipboard contents remain usable after the Share picker closes and temporary share files are cleaned up. Copying does not leak or retain the temporary export directory.
- [ ] Define and cover the multi-photo Copy behavior: where the system supports multiple images, Copy transfers the selected images; otherwise the UI makes the one-image limitation clear and never silently copies only an arbitrary item.
- [ ] Add a deterministic test around the pasteboard/service seam that checks the image representation and cleanup lifetime. Preserve existing Share picker presentation, cancellation, and HEIF-to-JPEG fallback behavior.
- [ ] `swift build` is warning-free and focused Share workflow tests pass; run AppKit/UI tests in the relevant CI lane if pasteboard integration changes.

## Implementation notes

Use native pasteboard representations and the existing rendered share output. Keep the image encoding and service choice inside the export/share boundary, not a SwiftUI button action. Do not claim that `NSSharingServicePicker`’s built-in Copy semantics are correct solely because the picker presents; verify the type written to the pasteboard and a real paste into an image consumer when available.

Related: KRMA-949 and KRMA-989 define Share rendering behavior; KRMA-1023 covers picker anchoring/presentation, which is separate from copied content.

### Comment — claude @ 2026-10-19T14:02:54.331Z

Cause (by inspection; not reproduced against a real paste): the picker's built-in Copy receives lazy NSItemProvider file representations, so it yields at best a file reference to a temp file that cleanup deletes. Fix: the picker delegate swaps the system Copy for a custom NSSharingService (ExportWorkflowCoordinator.makeCopyService) that renders every selected photo with the share size/quality/working space as JPEG and writes the bytes as public.jpeg NSPasteboardItems (one per photo, all-or-nothing). The pasteboard no longer depends on the temp directory, which is removed afterward. Multi-photo: all photos are written as separate items; targets that take one image use the first. Tests: service swap, pasteboard types and decodable bytes, cleanup. swift build 0 warnings; ExportWorkflowCoordinatorTests pass (key-window tests skip headless). Not done: real Slack paste check, fast/serial lanes. Left uncommitted next to pre-existing edits (including a SharePickerPlacement change from another task). Copy is matched by the title 'Copy', so a localized system title would append ours rather than replace it.
