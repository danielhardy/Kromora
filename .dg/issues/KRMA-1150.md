## Problem

After a crop, dragging the tone curve updates the preview, and releasing the pointer turns the frame black. Resetting the curve restores the photo. Dragging another control, such as exposure, flashes the image back while the pointer is down and black again on release. The reported edit also had a rotation, a subject mask, mask exposure, a global exposure change, and the Fine Mono look. Those stages stay in the graph either way. The frame goes black only while the tone curve is off identity and the settled render asks for a tile that misses the curve lookup.

## Cause

The tone curve is a 256×1 texture sampled by pixel value. The kernel's region callback returned the destination tile for that lookup. A settled preview renders only the visible crop, which usually does not contain the texture at the origin, so those tiles sample empty texels and render black. The smaller interactive frame often still covers the texture, which is why the photo stays visible until the drag ends.

## Acceptance criteria

- [ ] A crop that does not contain the 256×1 curve texture still renders the tone curve, rather than black.
- [ ] An identity tone curve and the existing tone-curve golden stay unchanged.
- [ ] Cached frames rendered before the fix are invalidated, so a previously black settled frame is refined.

## Reproduction

1. Open a cropped photo in Edit. Rotation, a mask, and a look can be present.
2. Drag the tone curve. The preview updates while the pointer is down.
3. Release the pointer. The frame goes black.
4. Reset the curve. The photo returns.


### Comment — cursor @ 2026-10-31T13:39:23.075Z

Root cause: the tone-curve kernel asked Core Image for the destination tile of the 256×1 lookup. A settled crop that misses that texture samples empty texels and renders black. The smaller interactive frame often still covers the texture, so the photo stays visible until the pointer is released. A mask and a look can be in the same graph; the black frame requires the curve and a tile that misses the lookup.

Fix: the lookup sampler requests its own extent (ToneCurveFilterCache). pixelEpoch advances from 38 to 39 so a cached black frame is refined. Regression: RenderPipelineTests.testToneCurveStaysVisibleInACropThatMissesTheLookupTexture. That test rendered 0 before the fix and a midtone after it. Identity curve and tone-curve golden tests passed with it.
