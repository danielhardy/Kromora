## Objective

Make a brush mask's identity a combination of per-stroke digests so that painting re-encodes only the stroke being drawn, and let `LocalMaskRenderer`'s stroke cache reuse the same digests. Child 5 of the KRMA-954 plan (`docs/RENDER_KEY_PLAN.md`); depends on the render-path threading ticket.

## Scope

- In `RenderDocumentIdentity`, compute a brush definition digest as a deterministic SHA-256 over the ordered per-stroke digests; reuse committed stroke digests by `==` against the memo (shared storage makes this O(1) per unchanged stroke).
- `LocalMaskRenderer` (stroke cache keyed today by `RenderCacheHash.digest(stroke)` plus `digest(transform)`) uses the memoized per-stroke digests instead of re-encoding.
- Extend `RenderKeyHashingBenchmark` with a paint-tick scenario: append one sample to the last stroke of the large recipe each tick and time identity work per request.

## Acceptance criteria

- [ ] Paint-tick identity work on the large recipe scales with the active stroke, not the whole mask: report before/after; target < 1 ms per tick for a 512-sample active stroke.
- [ ] Tests: reordering strokes, editing a committed stroke's radius/feather/flow/density, or appending a sample each change the definition digest; an unchanged stroke list keeps it; per-stroke raster cache hits are preserved for unchanged strokes.

## Rules every change here must keep (KRMA-954)

- [ ] Compute immutable identity once per relevant mutation; never JSON-encode and hash the whole document on every repeated interaction.
- [ ] Session-local caches may use revision or structural keys; durable cross-launch identity keeps a stable digest (`EditDocument.editHash` bytes unchanged — the golden test stays green).
- [ ] Never persist Swift's randomized `Hasher`/`hashValue` output (no file, frame signature, edit revision, report, or string that leaves the process).
- [ ] Do not remove source, Look, or pipeline-version fences (`RenderSourceFingerprint`, Look/LUT content fingerprint, `RenderPipeline.pixelEpoch`, `LocalMaskRenderer.version`, `RenderIdentity.current`, `PresentationFrameEnvelope.storageFormatVersion`).
- [ ] Texture pooling is out of scope (KRMA-963).
- [ ] Report before/after medians from `KROMORA_RENDER_KEY_BENCHMARK=1 swift test -c release --filter RenderKeyHashingBenchmark` for the plain document **and** the large 5-brush recipe, in the handoff comment and in `docs/TESTING.md` (render-key section).
- [ ] A unit test proves equal documents produce equal keys and that an edit to each relevant field changes the key.
- [ ] `scripts/ci-tests.sh fast` and `scripts/ci-tests.sh serial` exit 0.
