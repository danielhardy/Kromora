## Objective

Add selective edit copying from the photo context menu and Cmd-C.

## Context

Human review of KRMA-1080 noted that the context menu's “Copy Edit Settings” currently copies every
edit category immediately. It should match the existing selective-copy workflow and open a dialog
that lets the user choose which edits to copy. Plain Cmd-C should open that same dialog in the app's
photo-editing context, while native text-copy behavior remains available when a text control owns
the first responder.

`EditClipboardCoordinator` already owns the edit clipboard and selective-copy categories, and
`MenuCommands.swift` exposes “Copy Edits…” plus “Copy All Edits” (Option-Cmd-C). Reuse those paths
instead of adding another clipboard or category-selection model.

## Acceptance criteria

- [ ] The photo context menu labels the action “Copy Edits…” and opens the existing selective-copy
      dialog.
- [ ] The dialog uses the photo under the pointer as its source, including when it is not the active
      edit photo; the active photo uses its live document and inactive package photos use durable
      edits.
- [ ] Confirming copies only the chosen categories into the existing edit clipboard; canceling
      leaves the clipboard unchanged, and source-read failures are reported without replacing it.
- [ ] Plain Cmd-C opens the same dialog when the app's photo-editing command context is active, but
      standard text controls retain native Cmd-C behavior. Option-Cmd-C continues to copy all edits.
- [ ] Tests cover context-photo source resolution, selected categories, cancel/read-failure behavior,
      Cmd-C routing, and native text-control precedence.

## Implementation notes

Keep the work localized to the existing edit clipboard/menu routing and add focused tests in
`Tests/KromoraKitTests/`. Do not add a second clipboard or category-selection model.
