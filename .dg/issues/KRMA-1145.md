## Objective

Make the documented throwaway bundle ID effective for packaged smoke builds.

## Context

`docs/TESTING.md` tells operators to set `PRODUCT_BUNDLE_IDENTIFIER=<throwaway id>` before invoking `scripts/app-store-build.sh` with `KROMORA_VERIFICATION_BUILD=1`. The wrapper does not pass that environment variable to `xcodebuild`. A direct `xcodebuild -showBuildSettings` check with the environment variable set still resolves the production ID from `Config/Base.xcconfig`. The verification build can therefore use the production bundle identity while the operator prepares the library clone in a different bundle container, risking access to the wrong profile and making the documented isolation path ineffective.

## Acceptance criteria

- [ ] The documented verification build accepts a throwaway bundle ID and the built Info.plist contains that ID plus `KromoraAllowLibraryOverride=YES`.
- [ ] Standard App Store builds retain the configured production bundle ID and an empty override key; archive mode rejects verification-only settings.
- [ ] A focused test or build invariant covers verification and production identity behavior, and `docs/TESTING.md` describes the working command.
- [ ] The packaged smoke can target the throwaway bundle container and an in-container library clone without touching a real profile or library.

## Implementation notes

Keep the override scoped to verification builds. `scripts/verify-xcode-app.sh` currently checks the production bundle ID from `Config/Base.xcconfig`; update its expected identity handling if the verification wrapper needs to validate a throwaway ID.
