## Objective
Ensure RAW lens correction uses Apple's camera-dependent decoder capability where appropriate, and establish whether Kromora misses useful Sony embedded corrections, without inferring a defect from visual geometry alone.

## Context
RAWDevelopSettings leaves isLensCorrectionEnabled at Apple's per-image default unless an explicit saved value is present. The specified Sony ILCE-7CR DSC01104.ARW was unavailable during inspection. DSC01153.ARW reported support/enabled; this does not establish DSC01104 behavior. Apple exposes one capability and does not document the exact scope of geometry, chromatic aberration or peripheral illumination through that switch.

## Acceptance criteria
- On available representative Sony ARWs, including DSC01104 if obtainable, record decoder version, image properties, isLensCorrectionSupported and initial/effective isLensCorrectionEnabled. Compare supported enabled vs disabled at full resolution with registered straight lines, extents, edge color and illumination; distinguish Apple's behavior from Lightroom profile choices and metadata interpretation.
- Trace preview, export and saved override behavior; confirm identical correction policy and geometry, accounting for preview scale. Identify whether separate CA/illumination control is actually available rather than assuming it.
- If a reproducible deficiency exists, make the smallest appropriate capability-aware integration behind the existing unified editor, with explicit defaults; existing edits may change appearance and need no legacy-rendering path. If Apple's per-image default is already correct, record the no-change outcome and evidence; do not turn on unsupported controls or add a profile database without evidence.
- Add focused tests for capability gating, saved overrides, preview/export parity and applicable cache/geometry, and run appropriate affected and serial checks. Preserve manual crop/perspective and do not add a Develop panel.
