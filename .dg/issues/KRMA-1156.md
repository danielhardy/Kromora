## Objective

Make a package edit reproduce its Look from the package alone: resolve embedded Look bytes at load, and keep the embedded reference on later saves.

## Context

Source: audit `.context/audits/2026-11-03-code-quality-audit.md` (against `b7e46d5c`); probe source and outputs are in `.context/audits/evidence/2026-11-03/README.md`. Line numbers below are from that commit and may drift.

The package writes embedded Look bytes and has a checked reader, `readEmbeddedLook` (`Models/PortablePackageEditSidecar.swift:957`), but nothing calls it. `LookSelectionCoordinator.resolve` (`ViewModels/LookSelectionCoordinator.swift:57`) searches only the scanned external library and the in-memory derived registry. Separately, `sourceLookBytes` (`Models/EditDocumentStore.swift:475`) uses only the currently supplied external-byte dictionary, so an ordinary edit saved after the external file is gone drops the embedded reference while keeping the LUT ID.

Probe on the production persistence/resolver: embedded bytes match and the fresh load is ready, but `runtimeResolverFoundLook=false` and `embeddedReferencesAfterOrdinaryEdit=0`. Effects: ungraded live preview, or a failed per-asset export (the safe behavior), after a package moves to a Mac without the external cube. An external file replaced at the same path can also change an old revision's look. This breaks the documented contract that moving or deleting an external cube must not invalidate a saved edit.

## Acceptance criteria

- [ ] A shared, content-addressed package Look loader resolves a saved revision's Look from embedded bytes, verified against the stored hash, and is used by the editor, thumbnails, history/restore, and export.
- [ ] An ordinary save of an edit whose Look is unchanged carries the existing verified embedded reference forward, even when the external file is missing.
- [ ] Opening a package copied into a profile without the external LUT folder renders the same pixels as the original session for the current revision and for restored snapshots, and exports it.
- [ ] A same-path external replacement or a retired starter ID does not silently change a saved revision; an intentional library rescan or user re-selection still produces a new edit. Document this in `docs/LOOKS.md`.
- [ ] No fallback substitutes a nearest starter Look while claiming exact reproduction. A truly unresolvable Look still fails export visibly and keeps the stored reference.
- [ ] Tests: fresh-store/fresh-resolver reopen, edit-after-reopen retains the reference, snapshot restore, export, replaced-file, and retired-ID cases. Rendered-pixel comparison covers at least the reopen and export cases.

## Implementation notes

- Keep explicit user audition/rescan behavior separate from reproducing a saved revision.
- Check `RenderEngine` Look inputs stay inside the engine boundary (CLAUDE.md render rules).


### Comment — claude @ 2026-11-03T17:12:12.667Z

Implemented in 9a50791f. Saved revisions now resolve their Look from the embedded, hash-verified package blob (StoredLookRegistry, published by EditDocumentStore on load/save/revision select) and the editor, thumbnails, admission, idle warmer and export all resolve through LookSelectionCoordinator.resolve(_:for:). Ordinary saves and snapshots carry the verified reference forward when the external file is missing or replaced; re-selecting the Look in the browser adopts new bytes. An unloadable blob is only replaced by a library Look with the exact stored hash, so export still fails visibly. Contract documented in docs/LOOKS.md. Tests: Tests/KromoraKitTests/EmbeddedLookResolutionTests.swift (reopen with pixel comparison, edit-after-reopen, replaced file, different Look, snapshot/restore, retired ID, unloadable blob, export with pixel comparison). Ran scripts/test-affected.sh, adjacent suites, and scripts/ci-tests.sh fast (all pass); serial lane not run (no render/Core Image/AppKit code changed). Known gaps: a virtual copy does not inherit the source photo's embedded reference, and session-only derived:// Looks have no bytes to embed until saved.
