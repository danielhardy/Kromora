## Objective

Make the Crop inspector’s Reset link visibly use Kromora’s copper accent instead of system blue.

## Context

The full-crop Reset action is in the Crop inspector header as a compact link. In the current build it still appears blue; the requested appearance is copper link text using the app’s semantic primary accent.

KRMA-720 moved Reset into the pinned Crop title row and retained link styling. KRMA-725 added `.tint(KromoraTheme.primaryAccent)` to the shared semantic-link Reset button, but its verification noted that the source-level test could not prove the link style honored that tint at runtime. Treat the current visible blue as a rendering gap to reproduce and fix. Verify the rendered text color rather than simply adding the same tint modifier again.

This is limited to the full Crop reset link. Preserve its link affordance, placement, reset behavior, accessibility, and the styling of unrelated Reset links/buttons across the app. It is separate from KRMA-1044’s Cancel/Done action hierarchy.

## Acceptance criteria

- [ ] In the Crop inspector, the Reset link text visibly resolves to `KromoraTheme.primaryAccent` (the copper app accent) in both light and dark appearances; it does not render in the default system link blue.
- [ ] Reset remains a compact, unfilled link in the Crop header rather than becoming a prominent filled/capsule button or changing position.
- [ ] Activating Reset still restores the crop frame to the full image, with the existing accessible name and hint intact.
- [ ] The fix is scoped so other semantic links or Reset controls do not change unintentionally. If the shared semantic-link component is adjusted, verify its other callers or specialize the Crop treatment.
- [ ] Add focused coverage that checks the actual resolved/rendered foreground color or provides a repeatable live visual check; a source assertion that only confirms `.tint` is insufficient.
- [ ] Verify legibility, hover/focus behavior, and non-overlap at narrow and typical inspector widths in light and dark appearances. `swift build` is warning-free and focused Crop inspector tests pass.

## Implementation notes

Inspect the current `.link` button rendering on macOS 26 and determine why the existing semantic tint does not produce the requested visible copper. Prefer an explicit semantic foreground/style that still behaves as a link if `.tint` is ignored by the system link style. Keep dynamic light/dark colors in `KromoraTheme`; do not hard-code a static copper RGB value.

Related: KRMA-720 (Reset placement and link treatment), KRMA-725 (prior semantic tint change and its visual-verification limitation), and KRMA-1044 (separate Crop toolbar actions).
