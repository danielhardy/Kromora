## Objective

Produce a written design (an ADR under `.dg/decisions/`) for an explicit lease/release protocol that tells `RenderEngine` when a completed processing texture is safe to reuse. It is a design task. No pool and no engine change ships here.

## Context

Split from KRMA-963, which asked for a processing-texture pool and was closed without code. The per-render allocation in `RenderEngineResources.makeProcessingTexture` (`RenderEngineResources.swift:320`, called from `RenderEngine.swift:560` and `:2133`) stays until this design exists. Reusing storage before the GPU finishes or while a presentation still holds it corrupts pixels.

Findings from the KRMA-963 investigation:

- Completed textures leave the engine and `PreviewSurface` retains them in at least six places: `presentationTexture`, `transitionTexture`, `lastValidPresentationTexture`, `retainedCompleteTexture`, `pendingPresentationMaterialization`, and the histogram readback path.
- The engine is never told when those owners release a texture, or when GPU completion happens.
- No profile shows allocation cost. Per-render allocation may be fine.

Read the eviction code in `RenderEngineResources.swift` and `docs/ENGINEERING_GUIDE.md` (render/resource boundaries). Preview and export engines are separate instances. A pool must not be shared across them.

## Acceptance criteria

- [ ] Profile first. A window-independent measurement (Instruments or a test with an allocation counter, no `NSWindow`) shows whether per-render texture allocation is a meaningful cost at slider-drag rates. If it is not, the ADR says so and recommends no pool.
- [ ] The ADR lists every owner that can read a texture after `render` returns, with where each acquires and releases it.
- [ ] It proposes a protocol (for example a lease object released on deinit or completion, plus a GPU completion fence) that handles cancel, throw, memory-pressure eviction, and engine shutdown. It must respect Swift 6 strict concurrency with no `@unchecked Sendable`, `nonisolated(unsafe)`, or `@preconcurrency`.
- [ ] It describes a window-independent test that proves a texture is never handed out while an owner holds it.
- [ ] It ends with a decision: implement (with follow-up tickets), or don't pool (with the evidence).
- [ ] No display-bound capture is run. No source change beyond test seams needed for the measurement.
