## Objective

Make the packaged-app smoke identify its output from the export filename policy selected in the setup sheet.

## Context

`ExportCoordinator.lastUsedFilenamePolicy` persists the batch prefix, suffix, and Append Look setting in standard defaults. `scripts/smoke-macos-app.sh` currently waits for `000-Kromora-Smoke.jpg`, which only matches the default source-name policy with no prefix or suffix. A reused disposable profile can therefore complete export successfully but fail the smoke check because the selected policy produced a different name.

Relevant paths: `scripts/smoke-macos-app.sh`, `Sources/KromoraKit/ViewModels/ExportCoordinator.swift`, `docs/TESTING.md`.

## Acceptance criteria

- [ ] The smoke harness either reads the setup sheet's live example filename or sets deterministic prefix, suffix, and Look options through stable semantic accessibility labels; it does not rewrite app preferences or profile files.
- [ ] Output lookup and JPEG/dimension verification use the resulting selected filename.
- [ ] The packaged smoke passes in a confirmed disposable profile with both default naming and previously persisted custom naming preferences.
- [ ] `zsh -n scripts/smoke-macos-app.sh` passes, and the live UI result is recorded as executed or deferred accurately.

## Implementation notes

Keep the app's current selected naming policy visible and effective. Do not add a shipping alternate-library mechanism or touch a real profile/library.

### Blocking counterpoint finding — test library override is present in the shipping app

`Sources/KromoraKit/Presentation/AppLaunch.swift` reads `KROMORA_LIBRARY_PACKAGE` without a build-configuration guard. The Xcode app target links KromoraKit, so the App Store build can let an inherited absolute environment variable override the selected/default library at launch. This contradicts the implementation constraint against a shipping alternate-library mechanism, even though the smoke runs themselves passed.

Required change: restrict the override to explicit development/verification builds and prove that the standard App Store configuration ignores it, while retaining the disposable in-container smoke path.

Verification: add a focused test/build invariant that distinguishes the production configuration from the verification configuration; build the standard App Store configuration and verify the override is excluded; then run the smoke against a throwaway sandboxed bundle and in-container clone with default and persisted custom naming. Run `zsh -n scripts/smoke-macos-app.sh`. Do not point any run at a real profile or library.
