## Objective

An edit acknowledgement that does not change a photo's library summary must not rebuild or rewrite the library index.

## Context

Source: audit `.context/audits/2026-11-03-code-quality-audit.md` (against `b7e46d5c`); probe source and outputs are in `.context/audits/evidence/2026-11-03/README.md`. Line numbers below are from that commit and may drift.

`stagePresentedAspectRatio` (`Models/PortablePackageEditSidecar.swift:552`) returns the membership entry even when the presented aspect ratio is unchanged. The store forwards it to `applyCommittedMembership` (`Models/PortableLibrarySession.swift:1898`), which always calls `applyIndexDelta` (line 939). `LibraryIndexProjection.applying` then builds a dictionary of all entries, validates paths/duplicates, sorts the whole array, builds a new query controller and ID set, advances the generation, drops the ordered-query cache, and schedules a full JSON index write, on the main actor. A tone-only edit costs O(library size). Code-confirmed; latency not measured.

## Acceptance criteria

- [ ] An equal summary produces no delta: no index generation change, no order-cache invalidation, no projection write.
- [ ] Real changes (crop/aspect ratio, rating, flag) still publish and persist correctly; the transaction's atomic geometry guarantee is unchanged.
- [ ] A test applies repeated tone edits and asserts zero generation/cache/write changes, and another asserts a crop change still publishes.
- [ ] Record a Release timing of the same edit sequence at 10,000 and 100,000 assets (before/after) in the ticket. Do not run display-bound captures.

## Implementation notes

- Out of scope: coalescing real deltas or moving snapshot building off-main (note as a follow-up if the measurement still shows cost). Do not introduce a new database.
