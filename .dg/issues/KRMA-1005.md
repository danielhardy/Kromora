## Objective

Virtual copy and library removal must not renew the package lease on the main actor. The write itself still checks the lease.

## Context

`createVirtualCopy` and `removeFromLibraryOffMain` (`Sources/KromoraKit/Models/PortableLibrarySession.swift`, around lines 1253 and 1745) call `ensureWritableLease()` (around line 756) on the main actor. That calls `lease.renew`, which reads and durably replaces the lock (`PortablePackageTransaction.swift`, around line 320). The large transaction is already off the main actor. This preflight is not.

Other `ensureWritableLease()` callers exist (around lines 1217, 1342, 1701, 1711, 1839). Move the ones that run immediately before an off-main mutation. Do not move culling's dirty/retry behavior; that is KRMA-996. A UI call must not report success before the write's outcome is known, and a failed write must stay visible. Returning instantly while the write fails later is not done unless the failure still surfaces.

KRMA-1006 covers Settings validation and the shutdown index. Leave those functions to that ticket. Parent epic: KRMA-994. Review finding 10. No timings were measured; do not block this ticket on a benchmark.

## Acceptance criteria

- [ ] The main-actor portion of virtual copy and removal reads only in-memory state. Lease verification and renewal run on the worker that performs the mutation, and the mutation re-checks authority before it writes.
- [ ] A contended or expired lease still fails the operation with the existing error. The user-visible failure path still runs.
- [ ] Tests cover a successful copy and removal, and a lease failure that does not report success. Use a fake or a temp package. Do not require external storage.
- [ ] `swift build` is warning-free. `scripts/ci-tests.sh fast` exits 0.
