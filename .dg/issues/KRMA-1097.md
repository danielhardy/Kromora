## Objective

Align the production Xcode packaging with Apple's current project conventions in three coordinated steps, without changing what ships:

1. **Project at the repo root, app inputs in one folder.** `Kromora.xcodeproj` moves from `Xcode/` to the repository root, and the app's packaging inputs from `App/` (plus the root-level `Kromora.icon`) into a single `Kromora/` app folder.
2. **File-system synchronized group.** The `Kromora/` folder becomes a `PBXFileSystemSynchronizedRootGroup`, so `project.pbxproj` no longer lists individual files. The "no implementation code in the Xcode target" invariant is enforced by folder contents.
3. **Build-setting-driven Info.plist.** Identity, version and capability keys come from `INFOPLIST_KEY_*` and standard build settings in the xcconfig files. The checked-in plist keeps only keys with no build-setting equivalent.

The built, signed app must be functionally identical before and after: same bundle identity, versions, entitlements, resources, and icon.

### Why

Apple's sample projects and Xcode templates put the `.xcodeproj` at the root beside one app-named folder, use synchronized groups (the Xcode 16+ default) so file membership is not hand-edited, and generate `Info.plist` from build settings. This repo already requires Xcode 27, so none of this needs compatibility work. The payoff is a conventional layout, no `../` path indirection, no pbxproj churn, and one source of truth for version and identity. Nothing is broken today, so the bar is "no behavior change".

Recommended; deviate only with a documented reason.

```
Kromora.xcodeproj/            # moved from Xcode/; xcshareddata/xcschemes/Kromora.xcscheme travels with it
Kromora/                      # PBXFileSystemSynchronizedRootGroup
  KromoraApp.swift
  Assets.xcassets/

  Info.plist                  # reduced to UTExportedTypeDeclarations + KromoraGitCommit
```

Remove `App/` and `Xcode/` once empty. The local package reference changes from `relativePath = ..` to `.`.

## Implementation notes

- Suggested order, one commit each so a failure bisects cleanly: (1) capture the "before" artifacts; (2) move files and rewrite pbxproj/xcconfig paths, fix scripts and tests, get a green Release build; (3) convert to the synchronized group; (4) reduce the plist; (5) docs and link check.

- A root `Kromora.xcodeproj` beside `Package.swift` means a bare `xcodebuild` invocation in the repo root could become ambiguous. Scripts and docs must always pass `-project Kromora.xcodeproj`.

- Build outputs: relative `build/` directories appeared under the old `Xcode/` and repo root during earlier builds; confirm none are left untracked at the new root.
