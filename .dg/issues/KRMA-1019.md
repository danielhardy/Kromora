## Objective

Make package-backed batch culling undo restore every photo modified by the original action, including selected IDs without loaded rows.

## Context

`LibraryBrowsingCoordinator.persistUnloadedLibraryState` writes ratings and flags for unloaded selected photos outside the `ImageCollection` culling undo group. When a selection spans pages, Undo restores only loaded rows while the package metadata for unloaded rows remains changed.

## Expected behavior

One undo entry covers all loaded and unloaded targets from a batch culling action. Undo restores each photo through the same durable write and failure-reporting path used by culling updates, while preserving existing single-photo and batch selection behavior.

## Acceptance criteria

- [ ] With a three-photo package library and page size two, Select All followed by a rating change and one Undo restores the original rating for all three photos.
- [ ] The same coverage proves a flag change and one Undo restores every photo flag.
- [ ] Unchanged targets do not create spurious updates, and one batch action remains one undo step.
- [ ] Failed undo writes use the existing retry and error-reporting behavior.
- [ ] Unloaded IDs are handled in bounded chunks without decoding photo pixels.

## Implementation notes

Keep this focused on culling history for unloaded selected IDs; do not broaden selection or persistence APIs without need.
