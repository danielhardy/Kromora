## Objective

Carry the package-backed selection through culling, edit paste, and deletion when selected photos are not materialized in the current page.

## Context

KRMA-1001 now selects every matching package ID and selected batch export resolves unloaded IDs. The remaining actions still derive targets from loaded `ImageCollection` rows: `cullingTargetIDs`, `deletionCandidates`, and `AppViewModel.clipboardSelectedTargets`. With Select All on a paged library, these actions currently omit selected photos outside the loaded window.

## Expected behavior

Each package-backed bulk action uses the authoritative selected IDs, resolves only the metadata it needs, and processes those IDs in bounded chunks without decoding photos merely to enumerate the selection. Preserve per-photo edit history and RAW paste policy, culling write failure handling, and deletion confirmation and cleanup behavior.

## Acceptance criteria

- [ ] Tests use a three-photo package library with page size two, select all through the normal grid action, and prove culling, paste, and deletion include the unloaded selected ID.
- [ ] No action reads or decodes an image just to obtain the selected ID list.
- [ ] Large selections are resolved and processed in bounded chunks.
- [ ] `swift build` is warning-free and `scripts/ci-tests.sh fast` exits 0.

## Implementation notes

Keep the work under this parent issue; KRMA-1012's query-order cache remains separate.
