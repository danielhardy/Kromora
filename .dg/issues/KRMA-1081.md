## Objective

Restore visible, live preview updates from the Vertical and Horizontal Perspective controls in Crop
mode, then keep the selected perspective through Done/Cancel and the shared preview/export pipeline.

## Context

User report (2026-10-21): “in crop mode perspective controls have seemed to stop working.” The exact
photo, source format, affected axis, slider range, and whether the value readout moves are not yet
known; reproduce the report and record those details before choosing a root cause.

This is a regression follow-up to KRMA-487, which is done and should remain closed as the record of
the earlier defect. KRMA-487 found that `CIPerspectiveCorrection` changed raster extent while the
crop-mode `PreviewSurface` retained the planner's full-source extent. Commit `9547056` normalized the
corrected output to the expected geometry and added render/presentation assertions. Its verifier did
not launch the app for the manual slider check, so this report may expose a presentation regression
or a remaining gap in that verification.

Trace the whole live path rather than assuming the old fix is the cause:

- `Sources/KromoraKit/Views/CropInspectorView.swift` — Vertical and Horizontal slider bindings and
  their begin/end interaction callbacks.
- `Sources/KromoraKit/ViewModels/CanvasWorkflowCoordinator.swift` and the crop interaction state —
  transient draft values and reset/commit/cancel routing.
- `Sources/KromoraKit/ViewModels/PreviewAdmissionCoordinator.swift` — interactive crop request
  construction and publication/admission of each updated perspective value.
- `Sources/KromoraKit/Models/RenderPipeline.swift` — perspective correction, output extent, and
  composition with straighten, flip, rotation, and crop.
- `PreviewSurface` / `PreviewView` presentation and the regression coverage added for KRMA-487.

KRMA-479 and KRMA-481 describe adjacent live-geometry and crop presentation contracts. Preserve the
current project rules: macOS 26+ on Apple Silicon, Swift 6, Apple frameworks only, and matching
preview/export geometry. Do not remove perspective from interactive preview or weaken its visible
effect to work around latency.

- [ ] Identify and record the current regression's root cause, including whether each layer in the

- [ ] Add regression coverage that fails when a perspective-only interactive change is dropped or
      presented with incorrect geometry. Cover both axes, at least one nonzero sign for each, visible
      pixel change, and stable expected output dimensions; verify each live update reaches the
      presented preview rather than only producing an engine result.
- [ ] Preview and final export retain the same perspective composition. Done persists the draft;
      Cancel/Escape restores the committed values; Reset clears perspective; undo/redo of a committed
      crop continues to round-trip it.
- [ ] Manually verify both controls in the running app on a high-contrast building/tall-subject
      photo, including live dragging and release. Include a RAW source when one is available, and
      record whether standard and RAW sources behave differently.
- [ ] `swift build` is warning-free and the relevant crop/render tests plus `scripts/ci-tests.sh
      fast` and `serial` pass. Report unrelated flakes separately.

## Implementation notes

Start with the prior root-cause fix and its tests, then follow current request revisions through the
renderer and presentation surface. Distinguish a slider binding failure (thumb/readout does not
move), dropped/stale interactive publication (draft moves, frame does not), and a geometry/layout
error (new frame publishes but its shape is not visibly transformed). Keep crop drafts transient
until Done and do not change durable edit schema unless evidence requires it.

Related issues: KRMA-487 (previously fixed version of this symptom), KRMA-479 (live crop geometry
sliders), and KRMA-481 (crop presentation geometry).
