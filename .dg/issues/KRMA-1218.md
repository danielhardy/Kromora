## Failed behavior
Full-resolution export still rasterizes through `ExportRasterizer.live` and waits with `waitUntilCompleted()` while called by the shared `RenderEngine` actor. Thumbnail and idle-warm `makeCGImage` readback still calls `createCGImage` on that actor. RAW cache-miss development and RGBAh materialization can also occupy it. The visible preview can therefore wait behind background work. The existing canonical-frame test checks output values but does not deterministically hold background work while proving preview progress, and does not cover cancellation or stale source/revision safety.

## Expected outcome
Interactive preview requests make progress while export, thumbnail, idle-warm, and RAW background work is held or running. Preserve safe Core Image ownership and existing pixel output parity. Document all remaining contention. Keep the display-bound `concurrent-export-editing` capture deferred to a supervised performance session under repository policy.

## Acceptance criteria
- Isolate blocking export rasterization and background thumbnail/idle-warm and RAW developed-source readback from the interactive preview actor, using a safe Sendable resource boundary or separate engine ownership.
- Add deterministic tests that hold each relevant background operation and prove the visible preview progresses; cover cancellation, source/revision stale-result rejection, and output parity.
- Update `docs/TESTING.md` with any remaining actor contention and the deferred supervised capture.
