## Objective

Batch ("Export All") export lets the user choose how output files are named: keep the source name, and optionally add a prefix and/or suffix (for example `Wedding_` + `DSC01305` + `_web`). A live example filename shows the result. Single-photo export keeps its Save As name field.

## Context

The batch flow (`ExportCoordinator.batchExportDialog`, around line 483) is an `NSOpenPanel` that picks a folder ("Choose Export Folder" / "Export Here") with the same format accessory as single export. It already has no name field. The names come from `ExportFilenamePolicy` (`ExportOptions.swift`, around line 62), which has only two cases: `sourceName` and `sourceNameWithLook` (appends `_<Look>`). Users cannot add their own prefix or suffix. Naming is applied in `performBatchExport` (around line 694) through `filenamePolicy.baseName(source:look:)`.

Raised while reviewing the Export panel design (KRMA-1024). Do the layout work in KRMA-1024 first or together, since this adds controls to the same accessory.

## Acceptance criteria

- [ ] The batch accessory has Prefix and Suffix text fields plus the existing "append Look name" choice, with a live example filename built from the first item in the batch.
- [ ] Prefix and suffix are sanitized for filesystem-illegal characters (`/`, `:`, leading dots, empty result) and the example reflects the sanitized value.
- [ ] `ExportFilenamePolicy` (or a replacement type) carries the prefix and suffix, stays `Codable`, and decodes older stored values without loss. Last-used values persist like the other export preferences.
- [ ] Existing collision handling still applies, and two items never write to the same filename.
- [ ] Single-photo export is unchanged and does not show the prefix/suffix fields.
- [ ] Unit tests cover the naming (prefix only, suffix only, both, with and without Look, sanitization, collisions) and the Codable migration.
- [ ] `swift build` is warning-free and `scripts/ci-tests.sh fast` exits 0.
