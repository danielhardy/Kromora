## Objective

Decide whether Kromora ships a `PrivacyInfo.xcprivacy` privacy manifest and, if yes, add it to the app target. Record the decision either way.

## Context

Apple's privacy-manifest guidance and its Xcode templates ship a manifest with every app, but App Store enforcement of required-reason API declarations is documented for iOS, iPadOS, tvOS, visionOS and watchOS. `docs/APP_STORE_SANDBOX_AUDIT.md` (Required-reason API inventory, ~line 373) already concluded that no declaration is required for the macOS-only target, and `docs/APP_STORE_SUBMISSION.md` plus KRMA-807 deliberately do not rely on a manifest. No `PrivacyInfo.xcprivacy` exists in the repo.

This ticket is therefore a low-priority hygiene decision, not a submission blocker. Re-check Apple's current macOS wording before deciding, since enforcement could widen.

## Acceptance criteria

- [ ] Apple's current privacy-manifest documentation is re-checked for macOS and the finding is recorded in `docs/APP_STORE_SANDBOX_AUDIT.md` (update the existing inventory section, do not duplicate it).
- [ ] If a manifest is adopted: `App/PrivacyInfo.xcprivacy` declares no tracking, no collected data types, and the required-reason categories from the audit table (file timestamp, `UserDefaults`, and any others the table lists) with codes that match actual usage; it is in the Xcode target's Resources phase; `scripts/verify-xcode-app.sh` (or `app-store-build.sh`) asserts it is in the built `.app`.
- [ ] If not adopted: `docs/APP_STORE_SUBMISSION.md` states why and what would change the decision.
- [ ] `XcodeProjectInvariantTests` still passes (the manifest is a resource, not an implementation file).
- [ ] `scripts/app-store-build.sh` succeeds.

## Implementation notes

- Reuse the file:line inventory in the sandbox audit; do not re-derive it.
- `docs/PACKAGING.md` lists the contents of `App/`; update it if a file is added.
- If KRMA-1096 or a later restructure lands first, place the manifest in whichever folder holds `Info.plist`.

## Out of scope

- Fallbacks for earlier macOS releases or Intel hardware, third-party dependencies, `@unchecked Sendable`, `nonisolated(unsafe)`, or `@preconcurrency`.
- Restructuring `App/`, `Xcode/`, or the package layout beyond what this ticket states.
