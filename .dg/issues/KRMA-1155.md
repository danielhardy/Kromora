## Objective

Saving a named snapshot must never replace a newer durable edit, and the live editor and the package's current revision must agree afterward.

## Context

Source: audit `.context/audits/2026-11-03-code-quality-audit.md` (against `b7e46d5c`); probe source and outputs are in `.context/audits/evidence/2026-11-03/README.md`. Line numbers below are from that commit and may drift.

`EditHistoryCoordinator.saveSnapshot` (`ViewModels/EditHistoryCoordinator.swift:163`) reads `environment.currentDocument()`, awaits `flushPersistence()`, then calls `store.saveSnapshot(document, ...)`. The package's `commitEditRevision` (`Models/PortablePackageEditSidecar.swift:476`) makes the snapshot the *current* edit. Nothing fences edits made during the flush wait, and saving does not adopt the snapshot into the live editor.

Reproduced with the real coordinator and package store: start at exposure 0.1, request a snapshot, pause its flush, save exposure 0.9, release the snapshot. Result: `liveExposure=0.9 durableExposure=0.1 loadReady=true`. Reopening the photo can show the older image while every read reports success. Earlier revisions are still in history, so this is a current-state regression, not total data loss.

## Acceptance criteria

- [ ] Creating a named snapshot saves the captured document under the snapshot name without changing which revision is current, or is serialized/fenced so it cannot install an older captured value over a newer accepted edit.
- [ ] After the sequence "request snapshot, edit during the flush, edit during the snapshot write, reopen the package", the current edit is the newest accepted value, the snapshot holds the value captured when it was requested, and the editor, history list, and current-revision pointer agree.
- [ ] Navigating A -> B -> A around a snapshot request leaves the same invariants.
- [ ] Shutdown while a snapshot is waiting either completes it consistently or drops it cleanly; no write lands after the shutdown barrier.
- [ ] Regression tests gate both the flush and the snapshot write and cover the cases above against the real package store (reuse the audit probe as the starting point).
- [ ] Existing `EditHistoryCoordinatorTests` and `EditDocumentStoreTests` pass.

## Implementation notes

- Prefer a dedicated package operation (save-snapshot-preserving-current) over a coordinator-side retry; reading the document after one `await` still leaves other interleavings.
- Do not implicitly navigate history when saving a snapshot.
- Related: the history refresh fence in the "History refreshes" ticket covers read ordering; keep this ticket to the write path.
