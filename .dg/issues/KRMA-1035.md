## Objective

Show item-level and overall progress while Photos imports original resources stored in iCloud.

## Context

During KRMA-1031 review, `PhotosPickerImportProvider.readOriginal` was found to set
`isNetworkAccessAllowed = true` and await `PHAssetResourceManager.writeData`, but it does not
provide a progress handler. Large RAW downloads can therefore appear stalled while users wait in the
transfer phase.

## Acceptance criteria

- [ ] Transfer progress is surfaced per item and reflected in the Photos import progress UI while an
      iCloud original downloads.
- [ ] Progress updates are bounded and cancellation-safe; a cancelled or failed transfer still
      reports a clear per-item outcome and does not prevent later items from completing.
- [ ] The injectable `PhotosImportProviding` boundary supports deterministic progress in tests
      without PhotosUI.
- [ ] Tests cover progress delivery, cancellation, and a transfer failure; `swift build` and the
      relevant CI lane pass.

## Implementation notes

Keep original-resource selection and byte validation from KRMA-1031. Preserve the current per-item
failure behavior.
