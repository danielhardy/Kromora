## Objective

The Export save panel (NSSavePanel with a custom accessory) looks polished and consistently constructed: aligned, grouped, and native to macOS 26, with no behavior change to export options.

## Context

Seen in build `aef050e8`, and confirmed still present in a current `swift run` build (2026-10-15) (screenshot from the user: "this export window is terrible"). The accessory is built by hand in `ExportCoordinator.swift` (around lines 1000-1100: format segmented control, metadata checkboxes, "Also add to Photos" + album field, "Output sharpening:" popups). Observed problems:

- Controls have no shared alignment grid. The accessory content starts flush at the panel's left edge, while the system rows (Save As, Tags, Where) use a right-aligned label column. "Export format:" and "Output sharpening:" labels do not line up with it.
- No grouping or spacing rhythm. Format, metadata, Photos, and sharpening run together with inconsistent vertical gaps and no section separation.
- The sharpening popups ("None" / "Standard") are unlabeled individually, so it is unclear which is medium and which is strength.
- The "Album (optional)" field is a bare dark text field that stretches to the panel edge and does not match the other controls. It is not visibly tied to the checkbox, and should be disabled until "Also add to Photos" is on.
- The accessory touches the panel edges with no horizontal padding.

## Acceptance criteria

- [ ] The accessory uses one label column and one control column, aligned to the system rows above it, with consistent 8/12/20 pt spacing, and standard horizontal padding on both sides.
- [ ] Options are grouped into clearly separated sections (format, metadata, Photos, sharpening), with concise labels.
- [ ] Sharpening controls are labeled ("Sharpen for" / "Amount", or equivalent) so each popup's purpose is clear. The Album field is disabled until "Also add to Photos" is checked.
- [ ] Layout is built with Auto Layout (`NSGridView` or stack views), not manual frames, and holds at the panel's minimum width and when the panel is expanded and collapsed.
- [ ] Every existing option, default, accessibility label, and persisted preference behaves as before. Existing export tests pass; add a test that the accessory's controls still map to `ExportOptions`.
- [ ] Verified by screenshot of the running app in light and dark appearance.
- [ ] `swift build` is warning-free and `scripts/ci-tests.sh fast` exits 0 (serial too if an AppKit/UI test changes).

## Implementation notes

- Stay with NSSavePanel and the native accessory model. Do not replace the panel with a custom SwiftUI sheet unless that is a deliberate scope change recorded in the ticket.
- Swift 6 mode clean: no `@unchecked Sendable`, `nonisolated(unsafe)`, `@preconcurrency`, or `#available` branches. No new dependencies.
- Do not run `scripts/run-kromora-capture.sh`. Preserve unrelated working-tree changes.
- Related: KRMA-1023 (Share error, same build). Check the multi-photo and bundle export panels that share this builder. Batch export uses an NSOpenPanel folder chooser with the same format accessory (`batchExportDialog`); keep its layout consistent. Filename prefix/suffix for batch is tracked in KRMA-1025.
