## Objective

Switch the app to the Display P3 working space and prove nothing regressed and wide-gamut colors survive.

## Context

Part of the Display P3 epic KRMA-1114 (read its Context first). Until the final flip ticket lands, WorkingSpace.current stays .sRGB and this ticket must be behavior-neutral: sRGB renders, exports and cache behavior stay identical, and existing tests pass. Zero-opt-out Swift 6 rules apply (see CLAUDE.md). Run the deterministic lanes (scripts/ci-tests.sh fast, then serial for Core Image tests), not the display-bound capture harness. (This is the one ticket that changes the default.)

Preconditions: the policy decision ticket and the identity, Look-space, export, preview and Auto tickets are done. Flip WorkingSpace.current to .displayP3, set the export default per the decision, and update docs/ENGINEERING_GUIDE.md (remove the sRGB-canvas decision, record the new one) and docs/STORAGE_POLICY.md if needed.

## Acceptance criteria

- Existing Looks (bundled, user, derived, embedded) render identically to before in a fixed-document test, thanks to the authoring-space stamp.
- A wide-gamut test image with out-of-sRGB colors survives edit, preview and P3 export with no clipping; an sRGB export is still available per the decision.
- Saved edits from before the flip render the same (fixed-document test with an old package fixture).
- Full fast, serial and identity lanes pass.
- Docs updated; follow-up recorded for HDR/EDR.

## Out of scope

HDR/EDR, soft proofing.
