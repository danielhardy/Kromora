## Objective

Preserve the original resource filename when a first Photos import requests PhotoKit access and the user grants it.

## Context

`PhotosPickerImportProvider.originalFilename(for:)` calls `originalResource(for:)`, which fetches the `PHAsset` before any authorization request. `PhotosImportReviewCoordinator.begin` and `PhotosImportCoordinator.start` resolve and stamp the selection name synchronously. The first authorization request happens later in `resolveOriginalResource(for:)`, during inspection or transfer. If the initial fetch cannot see the asset but the later request grants access, transfer can retrieve the original while the review/import retain the generated fallback name.

Relevant paths: `Sources/KromoraKit/ViewModels/PhotosImportCoordinator.swift`, `Sources/KromoraKit/Models/PhotosImportNaming.swift`, `Sources/KromoraKit/ViewModels/PhotosImportReviewCoordinator.swift`, and `Tests/KromoraKitTests/PhotosImportNamingTests.swift`.

This is a source-review finding. The first-authorization filename path was not independently reproduced in a live Photos library.

## Acceptance criteria

- [ ] Name resolution waits for or follows PhotoKit authorization before deciding that the original filename is unavailable.
- [ ] When access is granted and an original resource exists, the review and imported package item use that resource filename.
- [ ] Denied access, limited-access misses, missing identifiers, and assets without an original resource retain a deterministic fallback name.
- [ ] Deterministic tests cover access granted after an initially unauthorized lookup and fallback behavior for unavailable resources.
- [ ] `swift build` is warning-free and focused Photos import/naming tests pass under Swift 6.

## Implementation notes

Keep the provider injectable and avoid changing public APIs or the package schema. Preserve the same resolved name between the review sheet and durable import. Verify `swift build` and focused Photos import/naming tests.
