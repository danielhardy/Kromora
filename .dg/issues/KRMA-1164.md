## Objective

The off-caller digest helper must never synchronously wait for hashing on the main actor.

## Context

Source: audit `.context/audits/2026-11-03-code-quality-audit.md` (against `b7e46d5c`); probe source and outputs are in `.context/audits/evidence/2026-11-03/README.md`. Line numbers below are from that commit and may drift.

`DurableEditIdentityMemo.Entry.resolve` (`Models/DurableEditIdentity.swift:25`) computes JSON and SHA-256 while holding the entry mutex. `cachedDigest` reads the same entry through the blocking `cached` accessor, and `digestOffCaller` (line 84) calls `cachedDigest` before hopping to its `@concurrent` worker. If another consumer is mid-hash for that document, the main-actor "cache check" blocks until it finishes. Equality checks over large distinct recipes also run under the shared lock. Code-confirmed; no timing claim.

## Acceptance criteria

- [ ] Completed digests are available through a nonblocking lookup; in-flight work is shared via awaiting (not blocking a thread).
- [ ] Lookup bookkeeping holds locks only briefly; hashing and large equality checks run outside shared locks.
- [ ] The durable hash format is unchanged (existing identity tests and stored values still match).
- [ ] Tests: gate a digest computation, request the same document from the main actor, and prove a main-actor heartbeat keeps running; cover different large recipes and cancellation of one of several consumers.
- [ ] `identity` lane tests are run for this ticket (it touches identity code).
