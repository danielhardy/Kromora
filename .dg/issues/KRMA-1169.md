## Objective

A missing or unloadable required image kernel must fail the render/export visibly instead of silently omitting a saved edit.

## Context

Source: audit `.context/audits/2026-11-03-code-quality-audit.md` (against `b7e46d5c`); probe source and outputs are in `.context/audits/evidence/2026-11-03/README.md`. Line numbers below are from that commit and may drift.

`CIKernelLibrary` (`Support/CIKernelLibrary.swift`) returns optional kernels, and several rendering helpers fall back to the input or current image when a required operation cannot be built, for example mask inversion/combination in `LocalMaskRenderer` (`Models/LocalMaskRenderer.swift:133`). Parity and resource-freshness tests guard the shipping bundle, but do not make runtime kernel or command failure impossible. A decorative overlay can degrade; a kernel needed to reproduce a saved local adjustment cannot yield a "successful" export without that adjustment. No damaged bundle was exercised.

## Acceptance criteria

- [ ] Required render capabilities are validated once, preserving the underlying load error.
- [ ] Pixel-producing document operations (local masks and adjustments) propagate an actionable render/export failure when their kernel is unavailable; optional presentation effects may still degrade.
- [ ] A failed GPU completion for an export surfaces as a failure and is not committed as a finished export; the document is preserved.
- [ ] No crash is used to report a recoverable rendering failure.
- [ ] Tests inject a missing/unloadable required kernel and a failed completion; existing neutral/no-op and unsupported-capability behavior is unchanged. Serial lane (`scripts/ci-tests.sh serial`) passes.

## Implementation notes

- Keep Core Image graph construction inside `RenderEngine` (CLAUDE.md). Classify each fallback site as required vs optional in the ticket before changing it.
