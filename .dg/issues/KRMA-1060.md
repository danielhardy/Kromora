## Objective

Implement the reviewed finite editor working set from KRMA-1059 while preserving edit durability, active undo, and stale-result fencing.

## Context and reproduction

Use the policy/defaults/integration map recorded by KRMA-1059. Current sessions retain complete per-photo documents and undo histories until removal or process exit. Add bounded retention at the existing document/persistence ownership boundary, not another document store. Clean evicted photos must reopen from package revisions, and accepted export/paste/history work must retain its immutable snapshots independently.

The critical race is an acknowledgement for revision N arriving after revision N+1 was queued: that must not make N+1 evictable. A selection-time durable read must also remain unable to overwrite a retained newer edit after old session bookkeeping was retired.

## Policy recorded by KRMA-1059

Authoritative text, rationale, and the 11 deterministic test scenarios are in `docs/EDITOR_SESSION_RETENTION.md`. Exact defaults and seams:

- Defaults on `EditorDocumentCoordinator` (constructor-injectable): `maximumResidentSessions = 32`, `maximumResidentSessionBytes = 192 MiB`. Cost = `(1 + undo + redo) x documentCost`; `documentCost` = 4 KiB shell + `MemoryLayout<BrushSample>.stride` per brush/retouch sample; no copy-on-write discount; computed on store, never on read.
- Recency tick stamped on `activate`, `commit`, `apply`, `adopt*` only; plain `session(for:)` reads do not touch it.
- Eligible for eviction: not the active asset or any outstanding `SourceSessionCoordinator.Request` asset, not grouping, and `!EditPersistenceCoordinator.isDirty(assetID)` (new; `pending[assetID] != nil`). Oldest tick first. Over budget when only pinned/dirty sessions remain; never drop unsaved values or trim the active history.
- Delete the `sessionRevisions` side dictionary: the revision lives in the resident entry; absent means `0` with `hadInMemorySession == false` (disk authoritative). `nextRevision` stays monotonic and is never reset.
- Run `evictIfNeeded()` from `persistence.onDurableWrite` and after `beginLoad`; drive it by `isDirty`, not by "an ack arrived" (old ack N while N+1 is queued must leave the session pinned).
- Undo contract: active undo and open grouping are never evicted; an evicted inactive photo reopens with a fresh undo stack at its saved state (existing cold-open behavior); durable revisions remain the recovery path; no seeding on reopen.
- **Required fix in scope:** `EditClipboardCoordinator.pasteEdits` applies to `session(for:)?.document ?? EditDocument()` for inactive targets, so a category-limited paste to a non-resident photo overwrites its saved edit with a neutral base. Load the durable document first; on read failure skip and report that photo, never fall back to neutral or the active photo.
- Probe `EditorSessionRetentionProbeTests` and the read-only `retainedSessionCount` / `retainedHistoryEntryCount` diagnostics already exist; extend the probe to assert the plateau.
