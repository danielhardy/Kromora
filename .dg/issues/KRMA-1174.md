## Objective
For RAW edits, route the existing global Exposure control through CIRAWFilter exposure, before the Look, while preserving the unified interface and standard-image RGB exposure. Deliver a calibrated and responsive implementation, or record concrete evidence if a decoder limitation makes a safe mapping impossible.

## Context
The user requests RAW-aware processing wherever suitable. Color white balance already routes RAW to RAWDevelopSettings. RenderPipeline.applyLight currently applies Light exposure through CIExposureAdjust after the Look; RAWDevelopSettings.exposure already configures CIRAWFilter before output. On macOS 27.2, 800px tests and fixed full-resolution crops of DSC00324.ARW and DSC01153.ARW show decoder and RGB exposure differ visibly; equal slider EV is not equal brightness. The flag crop exhibited stronger tonal separation with RAW exposure, but the test did not prove recovered sensor detail. Two DNG fixtures behaved differently. See docs/RAW_PIPELINE_INSPECTION.md and docs/rendering-experiments/raw-exposure/{RESULTS,FOCUSED_RESULTS}.md when present; these investigation artifacts may be local/untracked and are not required for deterministic tests. Preserve this factual distinction.

## Acceptance criteria
- Existing edits may change appearance; do not add a legacy-rendering path or migration solely to preserve their pixels. Keep stored documents readable and handle pre-existing nonzero rawDevelop.exposure and Light exposure coherently without accidental double application. Standard formats and local mask exposure retain RGB behavior. Test package save/reopen, undo, copy/paste, reset, comparison and export.
- Map the familiar global slider to decoder exposure exactly once; account for decoder defaults, capability and file-dependent behavior, and retain existing explicit develop settings without accidental double application. Define slider calibration and RAW/JPEG intent; do not promise equal pixel output. Maintain WB, masking and all existing controls.
- Verify render order explicitly: RAW exposure before Look; coordinate the corrections → Look → finishing order specified by KRMA-1178; until that work lands, do not introduce unrelated ordering changes. Validate preview, settled preview, histogram, Look candidates and full export consistency, and cache keys/invalidation.
- Add focused tests using fake and actual render boundaries; use optional real ARWs when available. Compare difficult bright/high-contrast and ordinary scenes at matched midtones, with Looks on/off, inspect channel detail and color; no claim that differing tone proves recovered highlights. Record any visible regressions and per-camera differences.
- Measure actual window-independent RenderEngine interactive first/settled work and cache counters across representative RAWs, p50/p95 and memory, compare current RGB path against new path. Reuse existing interactive RAW session and coalescing where effective; avoid stale frames. Report measured tradeoffs and resolve material regressions rather than relying on the standalone proxy (roughly 102–113 ms cold RAW vs 0.9–7.8 ms cached RGB at 800px).
- Follow CLAUDE.md targeted tests and required fast/serial lanes for affected shared/render code; do not run display-bound release capture. Update documentation and pixel/cache versions where needed.

## Relevant paths
Sources/KromoraKit/Models/{RAWDevelopSettings,RenderPipeline,RenderEngine,RenderCacheKey,EditDocument}.swift; Sources/KromoraKit/ViewModels/AppViewModel+Adjust.swift; package persistence and tests. No new user-facing Develop panel or separate editor.
