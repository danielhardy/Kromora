## Objective

Make every export path able to write either sRGB or Display P3 correctly tagged, per the policy decision, defaulting to sRGB until the flip ticket.

## Context

Part of the Display P3 epic KRMA-1114 (read its Context first). Until the final flip ticket lands, WorkingSpace.current stays .sRGB and this ticket must be behavior-neutral: sRGB renders, exports and cache behavior stay identical, and existing tests pass. Zero-opt-out Swift 6 rules apply (see CLAUDE.md). Run the deterministic lanes (scripts/ci-tests.sh fast, then serial for Core Image tests), not the display-bound capture harness.

Touch ExportOptions, ExportFormat, ExportCoordinator and ExportWorkflowCoordinator paths (batch export, single-file external editor handoff, Share, Copy, original-plus-settings bundle) and the export panel UI if the decision adds a choice. Each encoder (JPEG, HEIC, TIFF, PNG as supported) must embed the matching ICC profile.

## Acceptance criteria

- ExportOptions carries an output color space; the default preserves current sRGB behavior.
- For each supported format, a P3 export of a test image containing out-of-sRGB colors reopens tagged Display P3 with no gamut clipping, and an sRGB export reopens tagged sRGB.
- Existing export tests pass unchanged with the default.
- Panel copy (if any) is reviewed and does not name manufacturers.

## Out of scope

Preview, Looks, Auto, flipping the default.
