## Objective

Make every rendered delivery use the same target color space as the editing preview, with a matching
ICC profile, per accepted ADR-KRMA-1115. Prepare P3 without changing the current sRGB default.

## Context

Part of Display P3 epic KRMA-1114. WorkingSpace.current remains .sRGB until KRMA-1121; normal output
stays identical during preparation. Follow CLAUDE.md and run scripts/ci-tests.sh fast, then serial
for Core Image tests; do not run the display-bound capture harness.

Audit ExportOptions, ExportFormat, ExportCoordinator, ExportWorkflowCoordinator and panel settings:
batch export, Share, Copy, Photos delivery, external-editor handoff, and original-plus-settings
bundles. JPEG, HEIC/HEIF, TIFF and PNG must encode pixels in the selected pipeline target and embed
its ICC profile. An internal explicit target for preparation tests is fine; do not expose an
independent export-space choice or persist a preference that overrides the canvas target.

Share, Copy and Photos have no sRGB exception. External Editor retains 16-bit TIFF. Original bundle
bytes and their profile remain untouched; rendered companions follow the canvas target. The old
proposed sRGB-default policy is superseded by accepted ADR-KRMA-1115.

## Acceptance criteria

- All rendered delivery paths resolve their target from the same preview/delivery policy; no
  independent sRGB/P3 picker, remembered export-only space, or fixed-sRGB shortcut remains.
- For each supported format, an explicit P3 test export reopens tagged Display P3 and retains
  out-of-sRGB patches within documented format/precision tolerance. Explicit preparation sRGB
  renders reopen tagged sRGB; no untagged/mistagged output is written.
- Cover Share, Copy, Photos, external-editor TIFF and rendered bundle companions with the same
  explicit target; originals remain byte-identical.
- Existing default sRGB behavior passes until KRMA-1121 switches the canvas and all deliveries
  together. No independent sRGB delivery mode is exposed in the P3 release.

## Out of scope

Flipping the default, Looks, Auto, and implementing a future sRGB mode with matching preview.
