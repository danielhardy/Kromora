## Objective

Determine why DispatchGraph reports completed retouch issues as dependency-blocked when their direct and transitive dependencies are present and done. Fix the project-owned cause or document the external cause and its owner.

## Context

At KRMA-1063 verification completion, `dg issue show KRMA-1063 --json` reported `blocked: true` and `dependency_blocked: true`. Its direct dependencies KRMA-1062 and KRMA-1054 are done; KRMA-1062's dependency KRMA-1061 is also done and all three issue files appear in `.dg/.project/index.json`. However, dependency resolution reported those issues as missing. Determine whether this is a stale-index, resolver, or project-data problem before changing dependency records.

- [ ] Resolve the project-owned cause so completed issues with present, completed dependencies are not reported as blocked, or record the external owner and precise remediation if the cause is outside this repository.
- [ ] `dg issue show` and `dg validate` report consistent dependency state; preserve the historical verification reports and retouch verdicts.

### Comment — claude @ 2026-10-22T13:38:56.435Z

Finding: external cause, no project data change. .dg/.project/index.json is consistent (1043 issues; every depends_on target present, all of KRMA-1054/1061/1062/1063 done) and dg validate exits OK. 'dg blockers' correctly lists none of KRMA-1060/1062/1063. Only 'dg issue show --json' (dg 0.3.0+046b9b5) is wrong: for all 327 issues with depends_on (including 316 done issues whose deps are all done, and backlog/review ones) it reports typed_blockers status 'missing', dependency_blocked=true, blocked=true, regardless of --root. Dependencies on a genuinely open issue (e.g. KRMA-1076 -> KRMA-1086) resolve correctly through 'dg blockers'. So the show/--json dependency resolver fails to look up dependency issues; owner is the DispatchGraph CLI (dg issue show). Remediation: fix/upgrade dg; until then trust 'dg blockers' and 'dg validate', and ignore blocked/dependency_blocked from 'dg issue show' for issues with depends_on. Historical verification reports and retouch verdicts untouched.
