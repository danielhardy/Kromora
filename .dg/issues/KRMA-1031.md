## Objective

Importing from Photos stores the true original of each asset (the RAW file for a RAW photo) as the package original, never an edited or rendered rendition. The stored file's name, type, and bytes agree.

## Context

Found 2026-10-15 by inspecting a real import from the packaged app (full Photos access): `[local library asset path omitted]`.

- The source is named with a RAW extension, but its bytes are a JPEG/JFIF edited rendition rather than camera RAW. The import record stores the rendition without flagging the name/type mismatch.

Cause in code (`PhotosImportCoordinator.swift` lines 55-71): `transferData` uses `PhotosPickerItem.loadTransferable(type: Data.self)`, which returns the asset as Photos currently presents it (edited and/or rendered), while `originalFilename` reads the `.photo` `PHAssetResource`, the *original* filename. So an edited RAW lands as a JPEG with a RAW filename. The package guarantees "originals" (see `docs/STORAGE_POLICY.md`), and this silently breaks that guarantee and the RAW editing the product exists for.

This is separate from the `swift run` Photos-permission issue (KRMA-991) and the fallback naming (KRMA-1030).

## Acceptance criteria

- [ ] Reproduce with an edited RAW and an unedited RAW in Photos. Record the stored file type and pixel dimensions for each, before and after the fix.
- [ ] Import reads the original resource (`PHAssetResource` of type `.photo`, or `.alternatePhoto` for RAW+JPEG pairs) through `PHAssetResourceManager`, so RAW assets store the RAW bytes. If only an edited rendition is available (for example originals not downloaded), the user is told and the item is not stored as an original under a RAW name.
- [ ] iCloud-only originals: either download with network access and progress, or fail with a clear per-item message. No silent substitute.
- [ ] The stored filename's extension matches the stored bytes' actual type. A test (generated fixtures, no real photos) asserts that mismatched name and type are rejected or renamed.
- [ ] An import-time check flags a RAW-extension file whose bytes are not RAW (magic bytes), and reports it in the review sheet.
- [ ] Decide and record what to do with already-imported mismatched files such as `sample.arw`: list them (a diagnostic) and let the user re-import. No automatic rewrite of originals.
- [ ] Provider boundary stays injectable (`PhotosImportProviding`) so tests run without PhotosUI. `swift build` is warning-free and `scripts/ci-tests.sh fast` exits 0. Swift 6 mode stays clean.
