Failed behavior: Sources/KromoraKit/Presentation/AppLaunch.swift reads KROMORA_LIBRARY_PACKAGE without a build-configuration guard, and Kromora.xcodeproj links KromoraKit. The standard App Store build therefore allows an inherited absolute environment path to override the selected/default library at launch.

Expected outcome: The standard App Store configuration ignores KROMORA_LIBRARY_PACKAGE and resolves the library through normal settings. An explicit development/verification build retains a non-persisting override for an isolated package inside a throwaway sandbox container.

Acceptance criteria:
- Add a focused test or build invariant proving the production configuration excludes the override and the explicit verification configuration retains it.
- Build the standard App Store configuration and confirm the override is excluded.
- Run the packaged smoke with default and persisted custom naming against a throwaway sandboxed bundle and in-container library clone; confirm both JPEG names and dimensions.
- Keep the disposable development smoke path working and run zsh -n scripts/smoke-macos-app.sh.
- Do not access or modify a real profile or library.
