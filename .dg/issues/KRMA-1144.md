## Objective

Restrict the `KROMORA_LIBRARY_PACKAGE` override to developer and verification builds so the standard App Store build always opens the user's selected or default library.

## Context

`AppLaunch.libraryPackageOverride` currently reads an absolute `KROMORA_LIBRARY_PACKAGE` value unconditionally. `AppLaunch` is included in the KromoraKit code used by the Xcode app target, so the shipped app can bypass its stored library selection when launched with that environment variable. The override exists for isolated live checks and must stay available to the disposable development workflow.

Relevant paths: `Sources/KromoraKit/Presentation/AppLaunch.swift`, `scripts/disposable-app.sh`, `scripts/smoke-macos-app.sh`, `docs/TESTING.md`.

## Acceptance criteria

- [ ] The standard App Store build ignores `KROMORA_LIBRARY_PACKAGE` and resolves the selected/default library through the normal settings path.
- [ ] Developer and explicit verification builds can still use the override for a disposable library, without persisting it.
- [ ] A focused test or build invariant proves the production configuration excludes the override while verification coverage remains usable.
- [ ] `docs/TESTING.md` accurately explains the development and sandboxed verification isolation paths.

## Implementation notes

Keep this as a build-configuration boundary; do not add a customer-facing alternate-library feature or change persisted library selection. Do not touch a real profile or library.
