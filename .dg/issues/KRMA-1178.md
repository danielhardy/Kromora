## Objective
Implement a consistent corrections → Look → finishing order for RAW and standard images. A Look is a distinct creative color transformation over the corrected photo, rather than a set of slider values. Keep the unified UI and the existing LUT format/intensity semantics.

## Product decision and context
The user wants the Look after the core photographic edits so its role is coherent for RAW and JPEG. Existing edits may change appearance; this project has not been released, and no migration or legacy rendering path is required solely to reproduce prior pixels. Documents must remain readable and edits must not be discarded.

KRMA-1032 deliberately moved the Look before sliders in commit 9f3ae63d so that sliders adjusted the Look's output. The new decision supersedes that ordering. KRMA-1174 moves RAW exposure into development; standard-image exposure remains an RGB adjustment. Align this work with KRMA-1174, KRMA-1176 and KRMA-1179; avoid creating a dependency cycle.

## Required order
1. Develop and orient the source; apply global RAW-aware controls such as RAW white balance and exposure during RAW development. Keep retouch and geometry at their appropriate source stages.
2. Apply core global photographic corrections before the Look: standard-image global white balance and exposure, global Light tone/curves, global Color saturation, vibrance, mixer and grading, plus any corresponding persisted global adjustment nodes. RAW WB/exposure must not be applied a second time here. Resolve ordered legacy nodes explicitly and consistently; do not accidentally drop an edit.
3. Apply the selected Look as a distinct creative grade to that corrected image in its declared authoring space, retaining existing Look intensity and unresolved-LUT behavior.
4. Apply finishing: global spatial Effects and Detail, then ordered local mask layers, then crop, post-crop vignette and grain, followed by output conversion and optional output sharpening. Local exposure/WB remain RGB operations on the Look output. This explicitly defines the current requested treatment of finishing; document any indispensable exception discovered during implementation and why.

This aligns the Look's position relative to core corrections across formats; it does not promise identical RAW and JPEG pixels or identical numeric exposure response. Do not convert LUTs to slider values.

## Acceptance criteria
- Implement the above order for preview, comparison, histogram, Look-browser candidates, thumbnails, Save as Look and full-resolution export. Add pixel tests with non-linear LUTs and non-neutral tone/color controls that distinguish Look(corrections(source)) from the current order, cover RAW-aware and standard exposure routing, and establish the precise local/effects/crop/vignette/grain sequence.
- Preserve Look-only output, intensity 0/1 and intermediate blend semantics, LUT authoring color space, unresolved Look handling and neutral edits. Existing saved documents remain decodable, but their rendered appearance is allowed to change. No legacy pixel-preservation path is required.
- Test representative RAW and JPEG inputs with the same creative Look and comparable corrections. Measure and document LUT-domain clipping/gamut and slider response on bright and saturated scenes; explicitly report differences due to source decoding. Do not assume the LUT preserves extended values or that either order is universally superior.
- Update processing-prefix caches, candidate Look preview reuse, pixel/cache epoch and identities for the new order; ensure stale frames are invalidated, masks and source reuse remain correct, and no RAW re-decode occurs for RGB-only finishing changes. Measure window-independent interaction cost, especially Look browsing/intensity and spatial effects.
- Verify Save as Look sampling/support matrix, Derive baseline assumptions, preview/export parity and relevant real-engine tests. Update docs/LOOKS.md, docs/ENGINEERING_GUIDE.md, docs/APP_ARCHITECTURE.md and order comments. Run the affected set and applicable fast/serial lanes under CLAUDE.md. Do not run the display-bound release capture.
- Preserve all existing editing capabilities and standard-image support. Do not introduce a second editor, new Develop panel or third-party dependency.
