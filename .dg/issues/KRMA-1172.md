## Objective

When a user selects photo B while photo A has a settled preview parked in the renderer, B must reach the renderer without waiting for A. A late result for A must remain fenced from publication.

## Context

Counterpoint verification of KRMA-1166 exposed this separate failure in `Tests/KromoraKitTests/PreviewCutoverTests.swift`, `PreviewCutoverTests.testOrphanedSettledPreviewDoesNotBlockTheNextPhoto`. With `FakeRenderEngine.gatePreviews()` holding A, selecting B produced no B preview request within the test timeout; the recorded requests contained only A. A teardown release was added so the failure reports instead of leaving the test process waiting indefinitely. This preview-lane issue is outside the facet-count behavior in KRMA-1166.

## Acceptance criteria

- [ ] Selecting B after A is parked submits B preview work before A is released.
- [ ] A late completion for A cannot publish over the current photo.
- [ ] The focused regression test and `scripts/ci-tests.sh serial` pass.

## Implementation notes

Keep latest-request cancellation and stale-result publication fences intact while freeing the render lane for the current photo.
