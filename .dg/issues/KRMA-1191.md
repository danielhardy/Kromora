## Objective
Allow a user to double-click an adjustment slider’s thumb to reset that adjustment to its appropriate default, matching the existing double-click-on-label reset affordance.

## Context
Most editor adjustment sliders use `NeutralOriginSlider`, an `NSSlider` representable with a custom cell and tracking coordinator. `ResettableAdjustmentLabel` already invokes caller-provided reset actions, which can have semantics beyond setting a numeric zero; some defaults are nonzero or image-specific (such as RAW develop and white balance). Masking, crop, Look and other controls also use the shared slider, while a few sliders use other implementations. Audit the adjustment sliders and their existing reset semantics rather than assuming every slider's visual neutral is its reset value. Preserve existing label and accessibility actions.

## Acceptance criteria
- Double-clicking the thumb of each applicable editor adjustment slider resets only that control to the same default as its existing reset action, including nonzero and image-specific defaults. Cover global and local-mask adjustments and identify any sliders without a meaningful reset rather than assigning arbitrary defaults.
- A double-click on the thumb triggers one reset without a residual drag or stray value change. Single clicks, track clicks, dragging, keyboard operation, disabled controls, and slider accessibility continue to work normally; the reset gesture is restricted to the thumb rather than unexpectedly resetting on a track double-click.
- Reuse the existing reset pathways where available so undo/redo, edit grouping, preview updates, persistence and dependent state remain correct. Reset is a discrete undoable action where the corresponding existing reset is undoable; no-op resets create no spurious changes.
- Add focused tests for thumb versus track hit handling and gesture interaction, representative zero, nonzero and image-specific defaults, and undo/redo or existing reset integration. Verify applicable editor slider families, including shared and any separate implementations; document any intentional exclusions.
- Follow CLAUDE.md targeted testing and the required serial lane for AppKit/UI changes.
