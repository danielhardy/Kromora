## Objective

Make the long-gesture checkpoint test deterministic under fast-lane load.

## Context

`scripts/ci-tests.sh fast` has intermittently failed at
`EditPersistenceIntegrationTests.testLongGestureCheckpointsIntermediateSnapshotsBeforeMouseUp`
with only one intermediate write observed, although the test passes when run alone. During
verification of KRMA-1025, three full fast-lane runs failed at this assertion and two full runs
passed. The test currently depends on 300 ms wall-clock sleeps while expecting multiple 250 ms
checkpoints, so parallel test load can change when its persistence worker is scheduled.

## Expected behavior

The persistence checkpoint behavior remains covered by a deterministic test that distinguishes
intermediate snapshots from the final mouse-up flush. If controlled test scheduling reveals a
production checkpoint defect, fix that behavior without relying on timing luck.

## Acceptance criteria

- [ ] Replace wall-clock timing as the primary synchronization mechanism in the long-gesture
      checkpoint test with a controlled clock, gated store, or equivalent deterministic seam.
- [ ] The regression proves more than one intermediate snapshot becomes durable before the undo
      group ends, while still verifying the final snapshot flushes.
- [ ] The test passes repeatedly in isolation and under `scripts/ci-tests.sh fast`.
- [ ] `swift build` remains warning-free; do not add concurrency escape hatches or public API.

## Implementation notes

Keep this focused on the checkpoint test and its necessary internal seam. Preserve the real
250 ms production checkpoint interval unless deterministic coverage demonstrates a production bug.
