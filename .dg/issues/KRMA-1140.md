## Objective

Characterize and bound the remaining count-dependent memory growth in package RAW imports after
KRMA-1139 fixed retained file-read chunks.

## Context

An importer-only opt-in run on 2026-10-27 imported 240 full-size ARWs by cycling a 120-file fixture
set twice. On an M1 Pro with 16 GB and macOS 27.0.1, process footprint rose from 12 MiB to 131 MiB
before a per-source metadata autorelease pool and to 124 MiB after it. The 10-commit samples still
rose about 4–5 MiB each; the residual slope is approximately 0.47 MiB per imported file. The 240-file
batch stays below KRMA-1139's 1 GiB ceiling, so this is a broader follow-up to attribute and bound
the remaining growth.

Relevant paths: `Sources/KromoraKit/Models/PortablePackageImport.swift`,
`Tests/KromoraKitTests/PortablePackageImportMemoryTests.swift`, and `docs/TESTING.md`.

## Acceptance criteria

- [ ] Identify whether the residual footprint is live per-item state, Foundation/ImageIO temporary
  allocations, allocator high-water behavior, or another source, with repeatable evidence.
- [ ] Establish and enforce a finite working-set budget or backpressure policy for large batches
  without changing import identity, durability, cancellation, or per-item failure semantics.
- [ ] Measure a large RAW batch at intermediate checkpoints and document a ceiling and outcome in
  `docs/TESTING.md`; demonstrate that the supported batch remains well below physical memory.

## Implementation notes

Keep changes within the importer and its memory tests unless measurements identify another owner.
Use disposable/generated fixtures; do not modify an active library. Follow `CLAUDE.md` and
`.dg/AGENTS.md`.

### Comment — claude @ 2026-10-27T19:40:36.223Z

Root cause: autoreleased Foundation temporaries (path standardization and symlink resolution in commit and catalog work, URL and string bridging), retained because the whole batch runs in one worker job. Not live per-item state, ImageIO caching, or allocator high-water. Per-stage runs over 240 files showed slopes of 1 KiB (metadata, fingerprint), 60 KiB (stage and abort), 140 KiB (stage and commit), 447 KiB (full). heap listed 108k live NSPathStore2 and malloc_history placed them under PackagePath.url in commit. Fix: each source now runs inside its own autoreleasepool in PortablePackageImporter (control flow returned as a value, so identity, durability, cancellation and per-item failure handling are unchanged). Result: 240 files 124 -> 20 MiB; 1,000 files 24 MiB (3 KiB/file slope). Added testImportDoesNotRetainPerItemTemporariesAcrossABatch (fails at 39 MiB without the pool, ceiling 16 MiB) and an opt-in per-stage attribution test; docs/TESTING.md records the table, budget and ceiling. Checks: test-affected (13 tests, 0 failures) and ci-tests.sh fast (exit 0). Commit: see git log (KRMA-1140).
