## Objective

Provide a repeatable development-only way to preview the App Store system review sheet and reset Kromora review-prompt eligibility state for testing.

## Context

- `ReviewPromptPolicy` stores four local UserDefaults keys under `Kromora.reviewPrompt.`: `launchCount`, `finishCount`, `firstFinishLaunch`, and `lastRequest`. There is currently no UI to reset them.
- Clearing these app-owned keys resets only Kromora eligibility and cooldown. It cannot reset StoreKit eligibility or the App Store production display limit.
- Apple documents that development-mode requests display for testing, while TestFlight requests have no effect. The production API may choose not to show a prompt, so a shipping Settings or menu button that calls `requestReview` would not reliably fulfill a user action. See [StoreKit review request documentation](https://developer.apple.com/documentation/storekit/appstore/requestreview%28in%3A%29-1q8qs).
- KRMA-1093 already records that a persistent product-page link requires the App Store product ID, which is not in this repository. This ticket is only for a development test control; a customer-facing product-page link is separate work.

## Acceptance criteria

- [ ] A Developer section in Settings exposes review-prompt testing controls only in an explicit development build. They are absent from the App Store Release product and TestFlight distribution.
- [ ] A `Show Review Prompt` action invokes the existing system presenter with the current key-window content view controller, without changing `launchCount`, `finishCount`, `firstFinishLaunch`, or `lastRequest`.
- [ ] A `Reset Review Prompt State` action clears only the four `Kromora.reviewPrompt.*` keys and reports that only Kromora-local state was reset; it does not claim to reset StoreKit policy.
- [ ] The normal automatic review flow, two-finish threshold, later-launch requirement, quiet-app gates, and cooldown remain unchanged.
- [ ] Missing key window/controller is handled without crashing and is explained in the development UI.
- [ ] Tests verify the controls are development-only, reset only the four review keys, and invoke an injected fake presenter without presenting real StoreKit UI.
- [ ] A manual development-build check confirms the preview control can show the system sheet repeatedly. TestFlight and App Store production behavior are not used as deterministic preview checks.
- [ ] No custom rating/review UI, Settings toggle for normal users, or new entitlement is added.

## Verification

Run focused review-prompt and Settings tests plus the affected test set. Inspect the production build configuration to confirm the developer controls are excluded. Do not use a real customer or production StoreKit prompt as a test harness.
