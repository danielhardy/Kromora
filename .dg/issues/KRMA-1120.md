## Objective

Make Auto exposure/enhancement and photo analysis give the same results for the same photo regardless of working space.

## Context

Part of the Display P3 epic KRMA-1114 (read its Context first). Until the final flip ticket lands, WorkingSpace.current stays .sRGB and this ticket must be behavior-neutral: sRGB renders, exports and cache behavior stay identical, and existing tests pass. Zero-opt-out Swift 6 rules apply (see CLAUDE.md). Run the deterministic lanes (scripts/ci-tests.sh fast, then serial for Core Image tests), not the display-bound capture harness.

Touch PhotoAnalysis/CurrentEditMeasurement, AppleEnhancementReference, GlobalToneAnalyzer, MaskedToneAnalyzer, AutoEnhancementCoordinator, ContentAwareAutoEngine and ColorInspectorView/AppViewModel+Color. These measure rendered pixels; thresholds and reference values were calibrated on sRGB-encoded values and may shift in P3 encoding.

## Acceptance criteria

- Each place that measures pixels either measures in a fixed sRGB reference space explicitly (preferred, keeps results identical) or is recalibrated with the change documented.
- A test measures a fixed document with the space constructed as .sRGB and as .displayP3 and asserts equivalent Auto output within a stated tolerance.
- docs/AUTO_EXPOSURE_POLICY.md notes the measurement space.

## Out of scope

Export, preview, Looks.
