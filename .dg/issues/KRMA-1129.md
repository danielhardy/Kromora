## Objective

Default the derived-Look and in-memory cube authoring space to the current working space so a caller cannot silently create an sRGB Look from a Display P3 workflow.

## Context

Created from KRMA-1114 counterpoint verification. `DeriveCoordinator.makeDerivedLUT` and the in-memory `CubeLUT` initializer still defaulted `authoringSpace` to `.sRGB` after the Display P3 flip (ADR-KRMA-1115). Shipping derive and Save as Look already pass their space explicitly, so shipping output was correct; the risk was a caller relying on the default.

## Acceptance criteria

- [x] makeDerivedLUT and the in-memory CubeLUT initializer default to WorkingSpace.current, or every caller states its space explicitly.
- [x] Tests that depend on the sRGB default state their space explicitly; sRGB-specific fixtures keep passing.
- [x] scripts/test-affected.sh covers DeriveCoordinatorTests, CubeLUTTests, AppViewModelTests, PreviewCutoverTests, DeriveInvarianceTests and passes.
- [x] No change to shipping Look bytes or stamped headers.

## Implementation notes

`CubeLUT.init` and `DeriveCoordinator.makeDerivedLUT` now default `authoringSpace` to `WorkingSpace.current`. CubeLUTTests and LUTIDTests that relied on the sRGB default pass `.sRGB`. File writers still default to sRGB, and shipping call sites still pass the space explicitly. Implementation commit: 27a532b1.
