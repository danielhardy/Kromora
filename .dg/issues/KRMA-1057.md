## Objective

Prove that the warning-budget lane fails when either app or test compilation emits a Swift warning on the supported build path.

## Context and reproduction

Finding 5, enforcement slice. scripts/ci-tests.sh warning-gate runs swift build --build-tests -Xswiftc -warnings-as-errors, but on Xcode 27 beta / Swift 6.4 the October 19 Xcode-backed SwiftPM build emitted two PhotosReviewTransferCacheTests actor-isolation warnings and exited 0. Fixing that fixture alone does not prove that the configured gate actually enforces zero diagnostics.

After KRMA-1056, inspect the actual compiler/build invocation and reproduce the enforcement gap in an isolated disposable package or a stubbed build-command harness. Preserve diagnostic output and the builder's nonzero status. The reported packaging-tool AppIntents metadata note is separate from Swift source/test compilation warnings.

Source review: .context/2026-10-19-release-readiness-review.md (reviewed bb01e0c374fb; re-read current code because subsequent work may have landed).

## Acceptance criteria

- [ ] Establish and record why the current supported build path exits 0 despite emitted Swift warnings; verify effective flags/settings for both KromoraKit and KromoraKitTests.
- [ ] Make the gate reject Swift compilation warnings through compiler/build settings where possible; if output inspection is required, keep it narrow, documented, and unable to mask a failing build.
- [ ] Add a meaningful command-level regression: warning-free successful build -> success; emitted Swift warning in source and test compilation -> failure; ordinary compiler failure -> failure; full diagnostics remain visible.
- [ ] Exercise detection with a disposable fixture/stub instead of committing intentional warnings or mutating shipping source for a negative check.
- [ ] The actual app/tests warning gate passes with clean diagnostics after the fixture fix; CI and TESTING.md describe exactly what is enforced.

## Implementation boundaries

Do not add dependencies, warning suppression, concurrency escape hatches, or routine full clean/rebuild steps merely to make the output look clean. Demonstrate the negative test against the corrected enforcement.

### Comment — claude @ 2026-10-19T19:04:27.446Z

Reproduced in a disposable package (/tmp probe, Swift 6.4): -warnings-as-errors promotes ordinary warnings in both Lib and test targets (build fails), but XCTest lifecycle actor-isolation diagnostics (downgraded errors) stay warnings and the build exits 0; no -Werror group covers them. Fix: scripts/ci-tests.sh warning-gate now wraps the build in build_without_swift-warnings check that, after a zero exit, fails on any 'path:line:col: warning:' line (ANSI stripped; non-zero builds return their own status; full output still shown). Added warning-gate-selftest (stub builders: clean pass; source warning, test warning, compiler error fail; linker note passes), a CI step, a PackageSettingsTests wrapper, and TESTING.md text.
