Failed behavior: PreviewCutoverTests/testOrphanedSettledPreviewDoesNotBlockTheNextPhoto repeatedly times out after navigating away from a parked settled render; the second photo's opening render never reaches the engine. Expected outcome: navigation fences the abandoned result and admits the next photo render without waiting for the obsolete settled operation, while preserving scheduler lane limits and teardown behavior. Acceptance criteria: (1) the existing test passes reliably, including isolated rerun; (2) add or adjust focused regression coverage for cancellation of a parked settled predecessor and next-photo admission; (3) run the affected PreviewCoordinator/PreviewCutover suites and report results.


### Comment — claude @ 2026-11-12T21:52:25.506Z

Root cause: FakeRenderEngine's gated preview park used an uncancellable continuation, so after navigation cancelled the settled job, ImageWorkScheduler (which correctly holds a cancelled job's editor-lane slot in draining until its task returns) never freed the lane and the next photo's render never started. Fix is test-only: Tests/KromoraKitTests/FakeRenderEngine.swift parks now observe cancellation (with a registration-race guard). No production/scheduler change; lane limits intact. Extended PreviewCutoverTests/testOrphanedSettledPreviewDoesNotBlockTheNextPhoto to assert the second photo settles after release. Results: isolated test passed 3 consecutive runs; PreviewCutover, PreviewCoordinator, ComparisonMode, EmbeddedFirstFrame, PresentationBudget, WarmReopenPresentation, ThumbnailSwitchLifecycle: 99 tests, 0 failures.
