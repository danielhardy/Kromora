## Objective

Refine Crop mode’s action group to Cancel followed by one copper-primary Done action.

## Context

The current crop toolbar actions do not match the requested hierarchy. In Crop mode the user wants exactly one primary (copper) action, with remaining visible actions secondary; the action order should be Cancel, then Done, and the Undo button should be removed.

KRMA-864 corrected an earlier rendering problem where the toolbar became one tall orange pill, and KRMA-866 removed a duplicate Save/Cancel bar from the inspector. This ticket is a follow-up to the current visual/product preference: keep one action group in the window toolbar, with no duplicate commit/cancel row reintroduced in the inspector. “Remove Undo” applies to the Crop-mode toolbar button only; preserve document history and normal menu/keyboard Undo behavior unless an existing crop contract demonstrably depends on a separate control.

## Acceptance criteria

- [ ] Crop mode shows Cancel first and Done second in the primary action group, in that visual and keyboard/accessibility order.
- [ ] Done is the only copper primary button in the Crop-mode action group. Cancel and any other visible crop actions use secondary styling and do not appear as competing primary pills.
- [ ] The Crop-mode toolbar Undo button is absent. The change does not remove global Edit > Undo, keyboard shortcuts, or the underlying edit history contract.
- [ ] Cancel discards the active crop draft; Done commits it. Both actions retain their existing enabled states, focus behavior, labels, and accessibility descriptions.
- [ ] The inspector does not gain a second Cancel/Done row; existing crop inspector controls (including reset and geometry controls) remain available and correctly styled.
- [ ] Add or update focused UI/command assertions for button presence, order, style-role mapping, and Cancel/Done behavior. Verify the actual Crop toolbar in light and dark appearances at the supported window sizes.
- [ ] `swift build` is warning-free and the focused crop UI/model tests pass; run the appropriate serial lane for AppKit/SwiftUI presentation changes.

## Implementation notes

Use the existing app accent token for copper rather than a hard-coded color, and keep action semantics in the current crop workflow owner. Check the visible action group in both regular Edit and Crop mode so a hidden or duplicate toolbar instance does not retain Undo or a second primary accent.

Related: KRMA-864 (crop action rendering), KRMA-866 (duplicate inspector actions), KRMA-489 (Crop toolbar content), and KRMA-494 (crop/history semantics).
