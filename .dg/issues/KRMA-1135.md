## Objective

Remove repeated per-request hashing of mask definitions on mask overlay rendering.

## Finding

`RenderEngine.makeMaskOverlayImage` calls `resolvedLocalMasks` without `componentDigests`. The fallback in `Sources/KromoraKit/Models/RenderEngine.swift` builds digests for every component on the selected layer with `RenderDocumentIdentity.maskComponentDigests(for:)`. This encodes and hashes brush definitions even when `onlyComponentID` selects one component, and repeats that work on later overlay requests. Large stroke recipes can therefore still pay their serialization and hash cost during mask overlay updates.

## Expected outcome

Reuse the memoized component definition digest for overlay requests, or compute only the selected component when identity context is unavailable. Repeated overlay renders should use existing cache keys without re-encoding unchanged definitions. Keep the source, definition, target size, quality, transform, and renderer-version fences, and keep payload validation.

## Acceptance criteria

- [ ] Repeated overlay requests for an unchanged large brush component do not re-encode or hash its definition; demonstrate with focused test or benchmark evidence.
- [ ] Requests with `onlyComponentID` do not hash unrelated component definitions.
- [ ] Existing mask-overlay identity, mask-cache, and semantic-mask supersession tests pass.
- [ ] No persisted identity format changes; durable `EditDocument.editHash` remains byte-identical.

## Verification blocker

The selected-component filter avoids hashing unrelated components, but repeated overlay requests still recompute the selected brush component digest. `BrushStrokeDigest.definitionDigest(of:)` rebuilds the ordered stroke-digest payload and hashes it on every call; its memo only reuses individual stroke digests. `testOverlayDigestsCoverOnlyTheSelectedComponent` checks selected IDs and retained stroke count, but does not demonstrate reuse of the completed component digest. This leaves the repeated-hash acceptance criterion unmet for large brush recipes.

Required change: memoize the completed session-only brush component digest for repeated overlay requests while its source is unchanged. Keep the memo bounded, invalidate it when the component source changes, and preserve cache-key fences, payload validation, and durable `EditDocument.editHash` bytes.

Verification: add a deterministic focused test or benchmark proving repeated requests for one unchanged large brush component do not recompute its completed definition digest, that unrelated components are not digested, and that editing the selected source changes its digest. Re-run `BrushStrokeDigestTests`, `RenderDocumentIdentityTests`, and `LocalMaskRenderingTests`.
