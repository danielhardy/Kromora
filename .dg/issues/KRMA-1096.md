## Objective

Move the Icon Composer bundle `Kromora.icon/` from the repository root into `App/` so every production packaging input lives in one folder.

## Context

`App/` holds the production packaging inputs (`Info.plist`, entitlements, asset catalog, branding) per `docs/PACKAGING.md`, but the app icon lives at the repo root as `Kromora.icon/`. Apple's Xcode 26 flow adds the `.icon` bundle directly to the app target; keeping it beside the other target inputs is the conventional layout. The root-level location is the only packaging input outside `App/`.

References to update: `Xcode/Kromora.xcodeproj/project.pbxproj` (file reference `path = ../Kromora.icon`, line ~21), `scripts/verify-app-icon.sh` (lines 13 and 52), and `Tests/KromoraKitTests/KromoraAboutTests.swift:107` (checks the pbxproj string `Kromora.icon in Resources`, which should not change). `ASSETCATALOG_COMPILER_APPICON_NAME = Kromora` in `Base.xcconfig` is name-based and should not change.

## Acceptance criteria

- [ ] `Kromora.icon/` is moved with `git mv` to `App/Kromora.icon/`; no copy remains at the root.
- [ ] The pbxproj file reference resolves to the new location and the icon is still in the Kromora target's Resources phase.
- [ ] `scripts/verify-app-icon.sh` finds the bundle at the new path and passes against a fresh Release build.
- [ ] `docs/PACKAGING.md` and any other doc naming the icon location are updated.
- [ ] `scripts/app-store-build.sh` succeeds and the built app still shows the icon (`Assets.car` / `CFBundleIconName` check in the verify script).
- [ ] `scripts/ci-tests.sh fast` passes.

## Implementation notes
