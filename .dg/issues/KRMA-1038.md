## Objective

Make it clear when Photos review cannot inspect every selected item because the retained-transfer budget is spent.

## Context

`PhotosReviewTransferCache.inspect` returns `nil` after the retention budget is reached. `PhotosImportReviewCoordinator.inspect` currently treats that the same as a failed inspection, then increments `checked`; the review UI can therefore show all items as checked with no indication that later items were not checked for library membership or filename/type mismatch. This can leave a duplicate selected without the usual review warning in a large batch.

## Acceptance criteria

- [ ] Distinguish items skipped because the retention budget is spent from items whose inspection completed or failed.
- [ ] Show a clear review state for uninspected items so users know membership and mismatch checks did not run.
- [ ] Preserve the bounded transfer policy and one original-resource transfer for confirmed items.
- [ ] Add deterministic tests for the budget-exhausted review state and retain existing membership, mismatch, and selection coverage.

## Implementation notes

This is a non-blocking follow-up to KRMA-1037. It does not require another review transfer for items beyond the budget.
