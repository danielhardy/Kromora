## Objective

Validate the slider-to-decoder exposure mapping beyond the four Sony ARWs used to select the
current 0.75 ratio, and document the intended RAW-versus-rendered-image slider response.

## Context

`RAWExposureRouting` currently maps every RAW slider stop to 0.75 decoder stops. The calibration
benchmark and RenderEngine cost comparison cover four Sony ARWs. Earlier experiments recorded
identical RGB and decoder exposure output at equal EV for two DNG files, which implies a different
calibration from the Sony ARWs. The shipped 0.75 mapping was not re-run on those DNGs. See
`docs/TESTING.md` (RAW exposure routing), `docs/rendering-experiments/raw-exposure/RESULTS.md`, and
`docs/rendering-experiments/raw-exposure/metrics/IMG_0370.json` / `IMG_0797.json`.

This is a broader calibration and visual-validation follow-up. The current mapping remains
documented as Sony-measured and does not claim equal pixels or recovered highlights.

## Acceptance criteria

- [ ] Measure representative DNG and non-Sony RAW files at multiple negative and positive slider
      settings, including values near the neutral point and the bright-scene shoulder.
- [ ] Compare the decoder path against the existing RGB exposure path at matched midtones with
      Looks off and on; inspect channel detail, color, and visible regressions without treating
      different tone as proof of recovered sensor detail.
- [ ] Decide and document whether one calibration is appropriate or whether supported file families
      need different mapping; state the intended RAW/JPEG slider relationship.
- [ ] Add real-engine coverage for any chosen mapping, including one-time application, retained
      explicit RAW exposure, preview/settled/histogram/Look-candidate/export parity, and cache
      invalidation or reuse.
- [ ] Save and reopen a package edit containing both Light exposure and explicit RAW exposure, then
      verify rendering still combines them once without changing the stored schema.
- [ ] Measure interactive first/settled work, cache counters, p50/p95, and memory on the added file
      families; record the tradeoffs in `docs/TESTING.md`.

## Implementation notes

Keep photo fixtures out of tracked `realworldtest/`; use `KROMORA_RAW_FIXTURE_DIR` for local files.
Use the existing window-independent `RAWExposureCalibrationBenchmark` and
`RAWExposureRoutingBenchmark` where applicable. Do not run the display-bound release capture.
