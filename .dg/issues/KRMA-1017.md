Failed behavior: the recovery protocol is not atomic with normal acquisition or lease renewal. recoverExpiredWriter renames manifest.lock away before creating its recovery lease, so ordinary acquire can win O_EXCL in the gap and start with the old transaction journal still present. Separately, renew can pass assertOwnership before the claim and later replace the newly installed recovery lease through writeDurably, allowing the former owner to remain authoritative during rollback.

Expected outcome: recovery, ordinary acquisition, renewal, and release must share a continuous ownership fence. No ordinary writer can start until recovery either rejects takeover without changing the current writer state or finishes recovery. A renewal already in flight cannot replace a recovery lease, and a former owner cannot publish after recovery takes ownership. Preserve the live-local-owner refusal and the dead-local recovery path.

Acceptance criteria:
- Add a deterministic real-package test that pauses renewal after ownership validation but before lock publication, races expired recovery, and proves either renewal wins with recovery contending before rollback or recovery wins and the stale renewal cannot restore ownership or publish.
- Add a real-package contention test that attempts ordinary acquisition during recovery takeover; acquisition must not obtain a writer lease while the interrupted journal is still pending.
- Verify journal, staging, and lock state after rejected takeover and after recovery failure; retry must recover safely.
- Keep the unexpired-probe, renewed-owner, live-local-owner, dead-local-owner, and crash-point tests.
- swift build is warning-free and scripts/ci-tests.sh fast exits 0.
Tests may use separate lease/session callers in one process with no shared in-memory lock; use a second OS process only if the same-process test hides either filesystem race.


### Verification blocker — transaction publication is outside the ownership fence

Independent verification found a remaining check-then-publish race. `PortablePackageTransaction.commit` calls `lease.assertOwnership` before each publish, but the assertion does not acquire the package fence and the following journal writes and filesystem moves do not hold it either. `recoverExpiredWriter` can therefore take the fence and replay/clean the journal after a former writer passes its ownership check but before that writer's next move. The former writer may then mutate package state after recovery has taken ownership.

Required change: make the transaction ownership check and its journal/publication mutations mutually exclusive with expired recovery. If the transaction obtains the fence first, recovery must contend without changing the writer, journal, or staging state; if recovery obtains it first, the stale transaction must not publish or recreate transaction state as though it still owned the package.

Verification: add a deterministic real-package test that pauses commit after its ownership check and before a publication move, races expired recovery, and proves both serialized outcomes. Assert the final target contents, lock owner/state, transaction journal, and staging state. Keep the existing renewal/acquisition/recovery race tests, then rerun `swift build` warning-free and `scripts/ci-tests.sh fast` to exit 0.
