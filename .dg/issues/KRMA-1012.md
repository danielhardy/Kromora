## Objective

Asking for the next library page must reuse the ordered id list for the current index generation and query instead of sorting and filtering the full index again.

## Context

`LibraryQueryController.page(at:query:)` (`Sources/KromoraKit/Models/LibraryQueryController.swift`, around line 648) calls `orderedEntries(query:)` on every page request. The review asks for one query result keyed by index generation. This is a performance and ownership cleanup, not the Select All bug. Authoritative selection is KRMA-1001. Do not change which ids are selected.

Parent epic: KRMA-994. Review, "one authoritative library selection and query order."

## Acceptance criteria

- [ ] Repeated `page` calls with the same index generation and the same query build the ordered id list once. A counter or test seam shows the second call does not rebuild it.
- [ ] A changed query, a changed index, or an index mutation builds a new list. Page contents and order stay identical to the current sort for the same inputs.
- [ ] Selection flags on the page still reflect the controller's selected ids.
- [ ] Tests cover two pages of one query, then a different query. `swift build` is warning-free. `scripts/ci-tests.sh fast` exits 0.
